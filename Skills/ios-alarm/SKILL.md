# iOS 闹钟

## 原子动作

编号用于组合步骤，不是新增工具。参数明确时自动执行，复用已有授权。

| 编号 | 单一职责 | 输入与完成依据 | 失败或未知时 |
| --- | --- | --- | --- |
| A01 | 明确一次响铃时间 | 标题、设备日期和时区；时间在未来且少于366天 | 真正缺少时间才澄清，不改为循环 |
| A02 | 确认能力与授权 | 仅Sela自己的闹钟，依据实际系统授权状态 | 权限错误不记为闹钟数量0 |
| A03 | 查询实际列表 | `alarm_list`；保留实际ID、计划与系统状态 | 总数与前20项分开，截断不能当作全部 |
| A04 | 创建一个闹钟 | `alarm_create` 一次，取得实际ID和计划瞬时 | 未知提交不换标题、时间或任务重建 |
| A05 | 按需核对计划 | 用实际ID与时间核对；数字日期先辨明2001参考纪元 | scheduled只证明已安排，不能证明已响铃 |
| A06 | 呈现结果卡片 | 宿主从同次真实回执展示大号时间、日期、标题与创建结果 | 不添加没有执行能力的开关，不把历史卡片当作仍启用 |
| A07 | 区分到点证据 | 系统告警界面、SDK状态和实际声音分别核验 | 操作员停止测试闹钟不算Agent具有停止工具 |

查询组合：A02→A03→A06。创建组合：A01→A02→A04→A06；核对或处理未知旧提交时使用A03/A05，不能直接重建。

仅使用 `alarm_list` 和 `alarm_create(title, start)`。这些能力来自 iPhone 宿主的 AlarmKit；没有宿主工具时，skill 不会新增能力。操作范围是 Sela 自己的闹钟，不是 Apple「时钟」的全部闹钟。

收到明确任务后按宿主自动模式执行，不重复要求点击执行或逐步批准。首次系统授权按实际要求处理；拒绝时报告权限不足，不当作空列表，不反复弹窗。用户已恢复系统权限后再以真实查询核对。Sela 的「App 连接 → Sela 闹钟」卡片用于查看授权状态和管理权限。

创建只传单行清楚标题及带时区的完整 ISO 8601 `start`；标题最多160字，时间必须在未来且少于366天。按设备日期、时区处理“明早”等相对时间；真正缺少时间才澄清，不擅自改为循环或更换目标。返回创建回执后，用实际 ID 和计划瞬时核对，不仅凭同名标题判断。

`alarm_list` 返回本 App 闹钟总数及前20项。保留实际 SDK 字段，不能把截断列表当作全部记录。当前宿主若以数字返回 `schedule.fixed._0`，其单位是自2001-01-01 UTC起的秒数；不是 Unix 时间。转换后核对原请求的瞬时和时区，不把编码约定不明的值猜成日期。列表未提供标题时，不发明标题字段或其他 App 的内容。

创建和 `scheduled` 回读只证明已安排，不证明到点展示、声音可听、送达或用户已处理。实际告警需独立观察系统界面；操作员点击系统停止按钮，不算 Agent 新增了停止工具。

宿主在可能写入前保存待核对回执。同一任务的未知结果不能用重试、换标题、换时间或重建绕过；保留真实 ID 和状态，先核对实际结果。停止任务会阻止后续派发，但不能承诺撤回已交给系统的闹钟。当前没有修改、删除、取消、暂停、贪睡、周期闹钟或计时器工具，不虚构调用。

查询或创建的下一步在后台等待返回 Sela 前台时，保留同一请求，不重新提交。用户停止或进程重启后不能因前台事件恢复旧任务。已安排的闹钟仍按实际系统计划核对，到点显示与声音另行验证。

真实创建完成后，保留宿主从同一SDK回执生成的对话闹钟卡片，以大号实际时间、日期、原文标题及创建结果展示，并随任务历史保存。例如实际设为9:10才显示9:10，不能从计划或助手文字生成成功卡片。历史卡片标明创建时结果，不把它当作当前仍启用的证明，不添加没有停止或修改能力的假开关。

按真实回执在 `finish.text` 报告 ID、时间、范围和剩余限制。实际验收范围见 [references/acceptance.json](references/acceptance.json)，不把准备、回读或离线检查算成真实响铃。
