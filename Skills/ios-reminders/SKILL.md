# iOS 提醒事项

## 原子动作

编号是步骤标识，不是新增工具；已有信息和授权直接复用，明确任务自动推进。

| 编号 | 单一职责 | 输入与完成依据 | 失败或未知时 |
| --- | --- | --- | --- |
| R01 | 明确事项和可选时间 | 保留完整标题；指定时间转为带时区瞬时，没有时间就省略 | 不自行增加到期时间 |
| R02 | 确定列表 | 用户指定名称或允许默认列表；目标存在且可写 | 目标不存在、只读或歧义就停止 |
| R03 | 查询与查重 | `reminder_search`，分别核对标题、列表、到期与完成状态 | 返回截断或同名不同列表不能证明已完成或不存在 |
| R04 | 创建一条提醒 | `reminder_create` 一次；取得真实保存回执 | 结果未知不换标题或列表重建 |
| R05 | 回读实际状态 | 任务要求核对或恢复旧提交时查询；使用实际到期字段 | 未返回时间不能编造时间，本地回执ID不能冒充系统对象ID |
| R06 | 呈现并保存 | 宿主从真实回执生成提醒事项卡片，报告实际结果 | 无成功回执不显示已添加；历史卡片不是当前状态 |

查询组合：R01→R03→R06。创建组合：R01→R02→R03→R04→R06；需要回读时加R05。停止后不再派发下一项。

优先使用宿主实际提供的 `reminder_search`、`reminder_create`。没有这些执行接口时说明缺少的连接；这份 skill 本身不能操作手机。沿用用户任务范围、原文和当前确认设置。

自动模式下，收到明确任务就直接调用所需工具并连续推进，不再逐条询问“是否执行”。只有宿主已开启逐步审核时才等待它的审核；系统权限与必要信息另行处理。用户暂停或停止后，不自行恢复。

## 原生操作

- 查询：`{"operation":"reminder_search","query":"准确标题或关键词"}`。`matched_count` 是实际匹配数；`returned_count` 可能受上限限制，`truncated=true` 时不能声称已返回全部。
- 创建：`{"operation":"reminder_create","title":"原文标题","start":"带时区的 ISO 8601 时间","notes":"用户允许的备注"}`。没有到期时间的提醒可省略 `start`；用户没有给时间时不要自行编造时间或时区。
- 宿主当前契约支持 `list_name` 时，用户指定列表必须在创建中传入其准确名称；如 `"list_name":"Sela测试"`。不存在、只读或同名歧义必须停止，不能改写到默认列表。旧版仅支持默认列表，不向旧版发送未知参数。
- 当前只有创建和查询。不要发明完成、修改、删除提醒的参数。

省略列表时才使用系统默认。新版查询和创建回执包含实际列表名称；旧版回执可能只有标题、到期时间与完成状态。以实际回执字段为准，不能推断未返回的列表或稳定系统对象 ID。去重也核对所属列表；相同标题在其他列表中不能冒充目标列表已完成。

新版创建的结构化回执以 `source=EventKit`、`state=completed` 标明实际保存。`local_receipt_id` 是本地回执，`system_item_id` 和 `collection_id` 是保存后系统对象与列表标识，不能相互替代；完整同步后系统标识可能改变。读取独立的 `title`、`collection_name`、可选 `due`，不按“·”拆名字。`due` 缺省表示实际未设置到期时间，不能借用请求时间。旧回执没有这些字段时保留其信息范围。

当前 `reminder_search` 的匹配项把未设置到期时间写为字符串“未指定”，把完成状态写为字符串 `"true"` 或 `"false"`；不能按非空字符串的真假判断是否完成。查询未返回系统对象 ID 时，用创建回执保留的真实 ID，不声称从查询中再次取得。只有原值明确为未指定时，最终结构化报告才可据实记为 `due: null`。

## 重试和结果核对

1. 对网络中断后的重试、未知提交或用户要求避免重复的任务，先查准确标题，并结合到期时间与用户要求核对。不同日期的同名提醒不能自动当作重复项。
2. 遇到确认页就等待确认。没有出现成功工具回执前，不报告已创建；派发命令和助手文字不等于系统写入。
3. 宿主提示“上次提交结果未确认”时停止重发，先核对系统对象。保留原任务和回执，不能清理防重复记录来绕过保护。
4. 回执成功后如实报告标题、明确的时间及回执。需要验收所属列表、重复数或完成状态时，分别核对真实系统 App 或可用原生查询；只看可见片段仍有缺口。

“没有可写入的默认提醒列表”是列表准备问题。首次使用时可能需要完成系统「提醒事项」欢迎页、网络授权和列表初始化；授权成功本身不证明有可写列表。处理后查证旧提交，再使用独立测试编号或明确恢复，不盲目重放。

## 长任务

按用户清单分批推进，把每条回执关联到对应事项。区分成功、失败、未知、待确认和未执行项。尊重宿主的暂停、停止、进度保存与滚动上下文压缩；不自行添加总步数或 100 步上限。

成功后保留宿主从真实完成回执生成的对话提醒事项卡片，展示实际标题、列表与已返回的到期时间。未设置或未返回时间时不得编造时间；失败、未知或仅计划的操作不能显示创建成功。卡片随历史保存，表示当次结果，不代替当前系统状态查询。

真机验收范围见 [references/acceptance.json](references/acceptance.json)。这不是所有日期、账户和批量任务都已通过的证明。
