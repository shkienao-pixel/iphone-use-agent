# iOS 健康

## 原子动作

编号表示步骤，不是新增工具。每次`health_query`只处理一个类型和一个日期范围，按任务组合。

| 编号 | 单一职责 | 输入与完成依据 | 失败或未知时 |
| --- | --- | --- | --- |
| H01 | 固定范围与类型 | 明确时区、起止范围及steps/sleep/workouts | 不猜日期；汇总时先核对区间是否重叠 |
| H02 | 确认读取条件 | Sela前台、宿主工具和实际授权流程 | 权限错误与空结果分开，不循环请求 |
| H03 | 读取一个范围的一类数据 | `health_query`一次，取得真实HealthKit回执 | 保留失败或未知，不重复读取来补计数 |
| H04 | 解释可见结果 | 核对来源、范围、覆盖与截断；区分null和数值0 | 空结果不能证明没有记录或没有授权 |
| H05 | 记录完成身份 | 使用本任务已保存的真实完成元数据核对数量和完整区间 | 缺失或旧元数据不按计划补齐，不跨任务借用 |
| H06 | 按实际源值汇总 | 只计算已取得且类型、单位、范围明确的数值 | 元数据摘要不能还原健康值；卧床不能当已睡时长 |
| H07 | 呈现并保存 | 宿主显示真实结果卡片，报告覆盖与空结果限制 | 未知时长不能显示0，不生成医学结论 |

单项查询：H01→H02→H03→H04→H07。长任务逐段组合H03/H04/H05，要求数值汇总时执行H06；压缩或恢复不改变原范围。

使用 `health_query`，参数 `query` 仅为 `steps`、`sleep` 或 `workouts`，并给出带时区的 `start`、`end`。单次范围不超过 31 天。没有接口或设备不支持 HealthKit 时，不能用截图猜测健康数值。

只读取完成用户任务需要的日期和类型，不请求写入健康数据。尊重健康连接页已启用的类型以及系统授权；任务需要未启用类型时说明缺少的设置。沿用当前逐项确认设置。

自动模式收到明确读取任务后直接查询，不逐项再问是否开始；只有宿主开启逐步审核或系统需要授权时才等待。用户中断后停止后续读取，不因授权回调返回而自行恢复。

宿主等待 Sela 回到前台时，保留正在等待的同一请求；返回前台后由宿主继续，不重新发送任务或重复读取。后台等待不代表取得健康回执，也不计作有效业务执行时长。用户停止或进程重启后不能依靠迟到的前台事件恢复旧任务；先核对真实任务状态。实际后台行为以宿主回执和验收记录为准。

## 解释真实回执

- `steps`：累计可见步数。`has_visible_data=false` 或 `steps=null` 不能改写成“走了 0 步”。
- `sleep`：`asleep_seconds` 是范围内可见睡眠区间合并后的结果；重叠来源已去重。不要把清醒、卧床或抽样数当成睡眠时长。检查 `truncated`，超上限时不得称完整睡眠分析。
- `workouts`：返回实际运动记录与 `returned_count`、`truncated`，不将未返回记录当成不存在，也不自行把活动类型编号解释为未经核实的项目。
- `coverage=visible_data_only` 表示仅系统允许读取的可见数据。HealthKit 不揭示完整读取授权状态：空结果可能是没有记录，也可能是未允许读取；“已设置”仅说明执行过授权流程。

核对时对齐系统「健康」的日期、时区、数据类型和来源范围。不能用一次累计值一致证明所有来源准确，也不能从步数或睡眠记录作医学诊断。数据缺失、跨日和截断单列，不补造数值。

完成时把用户要求的实际结果、日期范围、可见记录数与限制写进 `finish.text`，不能只说“已汇总”。空结果的不确定性必须在用户可见报告中保留，不能只藏在原始工具日志。

长范围按不重叠区间分批读取，保留各批起止时间和覆盖说明；汇总前先检查边界和重复区间。原始健康值属于用户数据，不写进通用 skill 或公开验收样例。

宿主如提供 `current_task_only_health_read_completions`，可用 `identified_completed_reads`、`complete_three_scope_ranges` 和逐条真实完成元数据核对本任务读取次数与范围。它只在实际回执返回并保存后建立，不是计划清单，也不替代新的读取；相同范围的新读取有独立身份。压缩后沿用这些证据，不重新查询来补计数。旧记录缺元数据、无效项和未在账本中的调用保留未知，不跨任务借用。摘要与数量不能还原健康原值，也不能据此计算步数、睡眠或运动总量。此账本不证明完整授权、全部来源或备忘录保存成功。

成功后保留宿主依据真实HealthKit回执生成的对话健康卡片，展示实际数据类型、日期范围和可见结果，随任务历史保存。未知睡眠时长或不可见步数不能转换成0；卡片保留可见范围和空结果的不确定性。历史卡片不代替新查询，也不能从完成元数据摘要还原数值。

当前真机验收状态见 [references/acceptance.json](references/acceptance.json)。

首次使用先完成系统「健康」欢迎及隐私引导，不虚构个人资料。若允许工具读取后一直没有系统授权页或真实回执，不循环重发，也不报告已读取；停止任务并保留记录，再从 App 连接检查授权。已观察到单独授权页能显示、任务确认后授权等待不返回的差异，修复须另做真机验收。停止后需确认宿主执行已收束；系统授权若仍显示，处理它不等于允许旧任务继续读取。
