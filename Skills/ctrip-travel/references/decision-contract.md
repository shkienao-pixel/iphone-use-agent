# 携程决策与证据契约

供仓库维护、离线回放和独立评估使用。Sela执行模型当前只收到主SKILL.md，不能假设它读取了本文件。这里细化判定和验收，不增加工具或授权。

## 一批结果的身份

结果批次至少绑定：原始完整query、解析后的出行绝对日期、查询时间、来源类型、完整可解析方案序列。保留原始业务文本；展示重排不得改写原文、已保存的报价字段、用户草稿或工具写回执。

来源稳定顺序是本次合法来源中方案首次出现的次序。多段合并方案只占一个位置；共享航班保留源身份但不得因航班号不同编造不同起降时间。历史重复ID按候选位置保留，不能用ID过滤意外删除其他方案。

`flightSearch`和排序后的`flightOffers`必须同批；候选位置、UI顺序与连续追问一致。展开1→7→全部只改变可见数量，不改变批次或序号。新成功查询替换当前批次，包括成功零结果；失败保留的旧批次只能作为带原时间标识的历史资料。用户要求“原来那批”但来源不唯一时澄清，不拼接多批。

## 条件判定

先按用户原意分清硬条件和偏好。逐候选对每一条硬条件使用三值判定：来源明确符合、来源明确冲突、来源不足以判断。任何冲突归“明确不满足”；无冲突但有未知归“信息不足”；全部确认才归“已确认满足”。优先显示满足组，信息不足和冲突组带具体原因，不把它们重新命名成符合条件的首选。

人数条件与计价单位分开：用户说两位成人，不等于回执已证明方案适用两位成人；孤立“每成人500元”只说明单价口径。只有来源明确的方案人数，或有效回执明确的本次全局查询人数，才可继承对应人数；方案自己有冲突时不覆盖。人数未确认时多人适用性和多人总预算继续未知。

顶层起降机场与完整首/末段机场不一致时保留冲突，不自行选一个。若各记载在同一要求城市，城市条件可成立；例如首都与大兴均在北京，只说明北京出发可成立，不能证明精确首都机场条件。精确机场条件在此为未知，不能把城市一致当精确机场一致。

用户指定机场时检查机场而非只检查城市；指定到达期限时核对到达日期与时间而非起飞时段；预算涉及含税总价但税费缺失时不能仅用未含税价判预算满足。总耗时是全行程含等待的时间；不能只累加空中航段而忽略转机。跨日、时区或某段时间未知时不得补猜精确时长。

只有被用户明确改动的条件被替换。“不限机场”可解除原机场限制，“其他不变”必须保留日期、人数、舱位和期限等。不存在可确认满足的结果时，先说明结果边界，再合并询问最有用的一项调整；不自动放宽约束重查。

## 确定排序

硬条件分组在任何偏好之前。组内优先使用用户明确的排序顺序；未给出的默认键接在其后并去重。无明确排序时是：中转次数升序、含等待总耗时升序、可比金额升序、起飞时间升序、稳定来源索引升序。未知不得用0或缺省时间补成优势。

换乘/转机次数只能来自明确次数字段、明确直飞的0，或完整且可靠的N航段所支持的N−1。一个代码不是次数证据；经停不同于直飞，也不必然等于换飞机，不能因此填0或1。其次数不明时继续未知并排在已知后；若用户只要直飞，经停本身足以判该硬条件不满足。不能用空中航段时长或单代码为它补出更优次数。

价格键之前各维度相同的候选形成一组。只有全组报价币种、税费口径、人数及单价/总价口径明确一致才用金额；有混合或未知口径则全组跳过金额，使用后续起飞时间及源序，并明确不可混比。缺失金额放在已知金额后，但不能把税费缺失变成已知。不要通过币种/税费桶的字典序暗定偏好。这一分组规则避免pairwise“不可比就回退”导致排序环。

例如同为一名成人每人未含税报价可比较该未含税数额，但结论须限定此口径，不能宣称最低含税价。不同币种、未含税/含税混合、口径未知、每人价/整团价混合且人数不明，不跨组比较，也不无来源换汇。用户优先价格时同样遵守这些限制。

provider“综合推荐”“最划算”“适合商务”等文字不覆盖已确定规则。没有全量可比证据不生成最低/最短结论。排序规则默认仅内部使用；只在同一对话的实际用户明确修改已有结果排序后，展示一次简短变更结果。规范化query附带默认排序词不能触发展示；要求不解释或保持排序不变时隐藏。数据覆盖、金额口径等选择边界独立显示一次，不能随排序说明被隐藏；避免泛化推荐理由和正文重列每张卡。

## 宿主能力与失败状态

| 场景 | 当前能力及状态边界 |
| --- | --- |
| route | `flightQuery`完整request不超过4000字符；`clarify`收集必需缺失条件；纯解释不重查 |
| native query | `ctrip_query`只带query，工具自身上限4096字符；主流程4000兼容两入口；其他字段null |
| 请求来源 | 宿主验证响应来源与格式，授权由宿主管理；验证失败按整次错误处理。有效业务文本内的来源分区另按解析器scope判断 |
| 有限重试 | `CtripClient.queryFlights`只对明确实时报价服务不可用重试一次相同query；Skill不外加循环 |
| 不重试状态 | 成功零库存/无符合项、仅缺税费或行李、授权拒绝、限流、连接/超时失败；本轮按回执结束或由用户稍后重查 |
| 第二次仍不可用 | 清楚说明未取得实时报价；实际返回的时刻参考可以展示，但仍票价待查 |
| 请求取消/连接改变 | 不接续旧结果当本次成功，不清除取消或错误保护；连接变更后由宿主重新校验 |
| 用户暂停/继续 | “继续”只能请求宿主恢复；先走现有resume路由、归属与暂停校验。没有该协议或仍暂停时保持暂停，不把flightQuery当恢复 |
| 超时后的后续 | 本轮按失败结束，不因“继续”或缺字段额外自动查询；后续用户请求仍受宿主恢复/确认状态约束 |
| 数据缺失/截断 | 标缺失或截断，保留原始来源边界；不声称覆盖全部库存或所有候选 |
| 卡片交接 | 真实且经校验的航班专用链接可尝试；否则复制选择信息后打开携程App通用机票入口 |
| 无法交接 | 未安装、打开失败或缺少入口如实说明；不构造订单、付款链接或额外GUI流程 |

来源判断分为两层：传输/业务封装通过宿主验证之后，文本仍可包含官方查询与外部参考的不同区块。采用宿主解析器识别的标题和来源scope，保留已证官方的独立报价块；明确外部/时刻参考块只作未核价参考，不让外部金额、订票链接或推荐语混入报价身份。不能因一个外部块让已证官方独立块一并失败，也不能凭外部块自称携程把它升级。边界不能可靠归属时标待核实，不声称已经核价。

执行schema以本轮宿主提供的工具和route/action契约为准。此Skill不复制JSON schema，也不填造缺失的恢复、执行或交易协议；离线材料缺schema时只能报告语义方案，不能认证可执行JSON。

`CtripClient`存在业务文本长度保护，返回被截断时“全部”只指本次保留且完整解析的候选，不代表携程所有航班。Skill不能绕过宿主大小、来源或权限保护，也不能增加总task-steps上限。

## 卡片状态

每张大卡是一套完整行程；中转在同卡中逐段竖排，每段保留航班号、机场/航站楼、时间、明确日期和中间飞机图标。两段约为直飞双倍高度，但以内容自适应，不能用固定高度截断较长机场名或补充字段。来源明确的“全程总时长（含中转等待）”突出显示一次，不能拿空中时长之和替代；缺失就标待核实。等待、总耗时、机型、行李、退改仅采用源中明确内容。总价/税口径和硬条件状态应直接可见。

首屏只有一张候选大卡，更多先加6张，再显示其余所有完整候选；更多按钮在展开内容后，整行可点。候选不足时只展示实际数量。卡片字段不再逐项复制进正文；共同税费/行李/退改待核实合并为一次说明。只有时刻参考时使用明确的非报价样式与查价按钮。

## 原子动作及回执

| 步骤 | 输入与完成证据 | 失败边界 |
| --- | --- | --- |
| 固定请求 | 本次原始用户意图、对话、绝对条件 | 必需条件缺失只追问缺项 |
| 实际查询 | 完整query和实际业务回执 | 不因解析排版自动重查，不放宽条件 |
| 整组解析 | 原文、方案组边界、覆盖率、逐段数据及整套价格范围 | 未覆盖的可识别方案不能静默丢掉后宣称首选；零完整卡片仅短提示和默认折叠的原文 |
| 判定与排序 | 硬条件三值状态、明确优先键和稳定源序 | 未知不当满足；来源冲突不猜修正 |
| 卡片展示 | 当前批次、顺序、已展开数量、必要选择边界 | 不输出重复航班长文，不默认展示排序技术规则 |
| 固定交接选择 | 所选不可变方案、所属对话/消息或明确可见的任务详情 | 不能任意扫描历史任务以继承执行权 |
| 剪贴板准备 | 本次payload准备并核对成功 | 失败不继续打开，不展示旧剪贴板内容 |
| 打开目标 | 经校验专用入口，失败才通用入口；实际open回执 | 每个await后检查归属，切换后停止后续；单次在途保护避免双击并发 |
| 告知结果 | 分开记录复制和打开的真实成功/失败 | 不夸大预填、已选票、订单或付款；不把旧结果写进新对话 |

同一中转机场的明确日期与“过夜”等备注相矛盾时，只标该备注待核实，原文及独立有效报价保留。国际时区或机场不同而无法建立同一时间基准时，不用钟面推断冲突；来源未给出衔接保障时不能声称满足最短中转时间或保证赶上下一程。

## 证据分层

离线forward-test是使用限定原始材料的决策演练，不是实际接口或手机执行。离线parser单元检查、Mac真实查询、模拟器、真机UI、目标App落地页面分别记录；一个层级不能替代另一个。模型确认文字不等于工具回执。打开携程泛入口不等于选择已预填，更不是订单或付款成功。

独立评估只给用户请求、技能与最低必要原始材料，不给预期答案、怀疑点、修复方案或历史通过结论。案例文件没有expected字段；评估输出写隔离临时目录，不回写案例和产品文件。当前任务明确禁止网络与真机时，所有案例只演练拟用工具/完整query/用户答复，不触发真实调用。
