# iOS 日历

## 原子动作

编号是步骤标识，不是新增工具。复用已知信息和已有授权，按任务需要组合；信息齐全时自动推进。

| 编号 | 单一职责 | 输入与完成依据 | 失败或未知时 |
| --- | --- | --- | --- |
| C01 | 明确时间 | 用户安排、设备日期与时区；得到起止瞬时，结束晚于开始 | 只补齐真正缺少的时间，不猜时长 |
| C02 | 确定目标 | 明确的日历名称或允许使用默认日历；目标须存在且可写 | 不存在、只读或同名歧义就停止，不换目标 |
| C03 | 查询与查重 | `calendar_search`；核对范围、完整标题、起止时间和所属日历 | 截断时不能据此断言目标不存在 |
| C04 | 创建一个事件 | `calendar_create` 一次；实际完成回执含标题、起止时间、日历和回执身份 | 未知提交保留回执，不能自动再建 |
| C05 | 核对实际对象 | 任务要求核对或处理旧提交时，再查询准确范围与标题 | 同名但时间或日历不同不能算同一对象 |
| C06 | 呈现并保存 | 宿主从同次真实回执生成日历卡片，`finish.text` 说明结果 | 计划、失败和未知不能呈现为创建成功 |

查询组合：C01→C03→C06。创建组合：C01→C02→C03→C04→C06；需要独立回读时加C05。每次工具调用只完成表中的一个业务操作，校验步骤不产生写入。

使用实际提供的 `calendar_search`、`calendar_create`，保留用户原文及已明确的安排。没有执行接口时不声称已写入手机。

自动模式收到明确安排后直接执行所需查询与创建，不加“确认后才能开始”的对话。只在宿主已开启逐步审核、系统授权或确实缺少必要参数时等待。暂停或停止后须收到明确继续指令才恢复。

- 查询：`{"operation":"calendar_search","start":"2026-10-25T00:00:00+08:00","end":"2026-10-26T00:00:00+08:00","query":"关键词"}`。示例日期必须替换为用户的真实范围；所有时间带时区，结束晚于开始。
- 创建：`{"operation":"calendar_create","title":"原文标题","start":"明确开始时间","end":"明确结束时间","notes":"已授权备注"}`。缺少必要起止时间时先补齐，不虚构时长。
- 宿主当前契约支持 `calendar_name` 时，用户指定日历必须传入其准确名称，如 `"calendar_name":"Sela测试"`。不存在、只读或有同名歧义时停止，不能改用默认日历。旧版只能写默认日历，不向旧版发送未知参数。没有修改或删除操作，不发明 `calendar_id` 参数。

对重试和重复风险先查询相同日期范围与准确标题，结合起止时间和所属日历判断；同名但不同时间或位于其他日历的事件不能自动当作目标已完成。每个需要确认的操作正确等待。仅在真实成功回执后报告添加完成；对未知提交先查系统对象，不能靠换任务或清回执重复创建。

查询回执包含日历名称、起止时间和截断状态。单次返回上限不能当作总日程数；范围和时区必须与最终结论对应。验证所属日历和完整事件时，以系统日历中的实际对象为准。

新版创建回执是 `source=EventKit`、`state=completed` 的结构化字段：`local_receipt_id` 是 Sela 本地回执，`system_item_id` 与 `collection_id` 是保存后系统返回的对象和日历标识；三者不能混用。按字段读取 `title`、`collection_name`、`start`、`end`，标题和日历名中的“·”、引号或换行都是原文。旧版文本回执未返回系统 ID 时不补造。系统标识可能在完整同步后改变，不证明云同步或对象持续存在。

首次运行前检查日历访问权限与可写默认日历。授权页“已授权”不能替代真实创建、查询和系统对象核对。长任务保留各批结果及失败/未知项，暂停或重启后先核对检查点，沿用宿主长任务保护。

首次系统日历欢迎页可能尚未完成；出现无可写默认日历时先完成初始化并保留失败记录。系统设置里选中某个默认日历也不能替代真实写入目标核对。真机曾出现设置选中测试日历、实际创建仍落在原日历的差异；批量写入优先使用已支持的明确名称，并逐项核对回执，不批量试错。

成功后保留宿主依据实际回执生成的对话日历卡片，包含原文标题、实际起止时间和所属日历，并随任务历史保存。卡片表示创建时的结果；不手写虚构成功卡片，不从计划补齐未返回时间，也不把历史卡片当作当前系统对象仍存在的证明。

验收状态见 [references/acceptance.json](references/acceptance.json)，未通过的能力不得写成已验证。
