## 持续保留的约束

- 独立目录、独立 Swift Package；本版经用户授权将指南与既有加载入口合并，其他 skill、队列、原生工具和蓝牙执行器不在本模块内改写。
- 用户可表达复合目标；设备行为尽量原子化。一次输入、一次点击、一个滚动容器；核对不夹带提交。
- 联系人与动态分别确认；原文、原始日期、任务范围保持；不把昵称、列表位置或本地 UUID 当平台唯一标识。
- 用户明确要求发送就沿用授权，不另加重复确认；拟文案、填写与提交分别处理。
- 待核验不重发，已完成不重做；暂停、取消、恢复和上下文压缩保持独立结果。
- 真机测试、实际账号动作与规则核心的实时适配由用户后续安排。参考截图、语义 fixture、模型评测、真机验收分别记录。

## 每轮如何推进

1. 查看当前源码、上轮证据和真正的缺口；优先处理可能选错人、选错动态、重复提交或误报成功的问题。
2. 对具体缺陷先写最小行为反例，保留修复前结果；没有实际依据时不堆叠通用规则。
3. 只修改独立模块内相关实现、必要技能规则与引用。
4. 运行单一离线验证入口，保存实际测试明细、技能格式、隔离结果和源码指纹。未通过不能覆盖最新通过记录。
5. 报告做了什么、验证到哪一层、还有什么未知。不因单轮测试通过而标记全部完成；遵守用户显式暂停与恢复指令。

## 优先级

| 阶段 | 工作 | 完成依据 |
|---|---|---|
| 当前 | 提交生命周期与账本一致性 | 取消票据、结果时序、不可改写历史等反例先失败后通过；正常流程继续通过 |
| 当前 | 可复现验证 | 一条命令输出测试逐项结果、技能格式、源码身份与隔离报告，不手工填写通过数量 |
| 当前 | 准备阶段中断与准确续填 | 具体焦点与菜单归属、单次票据、部分输入只补后缀；完整回读不等于提交授权 |
| 当前 | 草稿跨进程检查点 | 持久化原任务、回读与未知意图；新资料/动态证明、提交状态和当前字段先核对；独立本地进程回放 |
| 当前 | 只读恢复与重新核对 | 新账号/动态证明、真实标记和顺序对应只用于核验待定效果；独立追加恢复证据；无法区分则保留未知 |
| 后续离线 | 候选范围与长任务增量进度 | 记录未展开候选、范围、剩余条件，摘要压缩后不丢原任务与结果 |
| 模型评测待安排 | 真实视觉模型的技能遵循 | 明确使用的模型、输入样本和独立判据；不把 Swift 分支检查称为模型通过 |
| 真机待用户安排 | 补齐菜单、输入、前后状态与端到端验收 | 当前 iPhone、真实截图与单次动作记录，逐项证明具体流程 |

未来无需为增加测试数而扩展范围。这里的阶段可按证据和用户新指令调整；不以未验证的成功率、提速比例或账号安全承诺作为目标。
