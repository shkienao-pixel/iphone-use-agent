# Sela 本地模拟器测试环境

本环境使用 Mac 上的 Xcode / iPhone 模拟器。Sela 是原生 iOS 应用，直接使用已有的 iOS 运行时即可编译、安装和自动检查界面；单独安装桌面虚拟机对这些测试没有必要。

Apple 说明模拟器适合开发与调试，但其硬件特性和性能与真机不同，具体硬件功能仍应在真实设备上验收：[运行到模拟器或真机](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)。

## 日常启动

双击仓库根目录的 `启动 Sela 模拟器.command`，或在仓库目录执行：

```bash
bash scripts/sela-simulator.sh run
```

首次搭建使用 `setup`。启动时复用专用实例；如果保存的源码已变化，会重新编译并核对源码身份，再覆盖安装到这个实例。此流程保留模拟器内的 App 数据。

```bash
bash scripts/sela-simulator.sh setup
bash scripts/sela-simulator.sh smoke
bash scripts/sela-simulator.sh screenshot
bash scripts/sela-simulator.sh status
bash scripts/sela-simulator.sh stop
```

- `setup`：创建并启动专用 iPhone 13 Pro、设置浅色和固定状态栏、编译、安装并打开 Sela。
- `run`：启动并打开专用实例中的 Sela，必要时自动更新构建。
- `smoke`：在同一个专用实例上运行 XCTest 界面检查，并保存结果和截图。
- `screenshot`：截图到 `output/simulator-lab/latest.png`；可加 `--output /绝对路径/截图.png`。
- `status`：显示专用实例身份和开机状态。
- `stop`：只关闭该专用实例。
- `build`：强制重新编译模拟器版本。

### 通知实现与后续验收

“设置 → 任务通知”提供独立的开关、真实系统权限状态及通知设置入口。开关默认关闭，主动开启时才请求系统授权；通知偏好独立保存，调整时不修改模型、确认方式和长任务设置。通知仅包含任务标题与状态，点击只打开指定任务记录。

生产引擎先观察到准备状态，才会为该次执行处理完成、失败、需要处理和等待确认事件。前台结果不主动提交通知；状态重复发布不重复提醒，新的确认步骤可以再次提醒，继续或切换阶段时清除被替代的通知。提交前持久记录事件，提交结果未知时不自动重发，记录保留最多 512 条。关闭开关会清除本 App 任务通知的待发项与已投递项。

代理在 App 完成启动前注册，以接收冷启动的通知响应，符合 [Apple 的代理生命周期要求](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/delegate)。实测发现异步代理桥接在冷启动时从后台线程完成回调，触发 UIKit 状态恢复断言；现改为显式 completion-handler 代理，并在主线程完成所有响应路径。原 SIGABRT 报告、失败版本和修复后 A/B/A 三次新进程启动及界面证据均已保留。

权限拒绝在主 iPhone 13 Pro 实例验证，允许及投递在不含模型密钥的 iPhone 17 Pro 实例验证，两台串行运行。修复后的三轮后台投递每轮只有一个新事件，八次重复状态均未增加通知；后台打开 A 时，B 记录已存在，仍准确打开 A，且引擎保持空闲。三轮冷启动先确认旧进程退出，再由系统通知启动新进程并核对 A/B/A 的实际界面。

系统通知设置链接在当前模拟器中落到了设置首页，此跳转未通过验收，也未通过重置权限或卸载 App 绕过。后台投递的 26.77 秒采样中，App RSS 峰值约 264.0 MiB；冷启动回归的 90.29 秒采样峰值约 447.5 MiB，属于 Mac 模拟器 Debug 进程。主实例重新进行一次真实对话仍返回 API 额度不足，原有对话完整保留。两台本轮管理的模拟器均已关闭，其他任务使用的实例保持原状。
