# Sela 测试与修复工程

验收对象是用户能否完成一件事、结果是否正确、出错后能否恢复。测试数量、编译成功、模型回答“已完成”，都不能代替这一结果。

## 工作方式

1. 从用户原话开始，走到真实结果、任务记录和重开后的状态；成功、拒绝、失败、取消、未知结果分别检查。
2. 先保留复现条件和原始失败，再修复。修复后跑对应回归、相邻状态和同一条使用流程。
3. 每项证据记录源码、运行环境、实际计费/认证路径和验证范围。离线替身、模拟器展示、真实系统调用、真实模型链和真机分别保存。
4. 每轮检查原有记录和草稿。等待超时不等于执行失败；先查原进程和回执，不能直接重发、重启或清空数据。
5. 成功路径与异常路径都验收后再关闭缺陷。依赖账户或系统条件的项目保持待验收，恢复条件后继续原场景。

## 风险优先级

| 优先级 | 影响 | 处理原则 |
| --- | --- | --- |
| P0 | 数据丢失、错误任务被控制、未知写入重复派发、失败显示成功、测试证据失真 | 优先复现修复；相应验收缺口阻止发布 |
| P1 | 核心流程无法完成、记忆错误或复活、取消失效、错误无法恢复、持续资源增长 | 与成功路径一起回归，不能以绕过功能交付 |
| P2 | 可恢复的布局、文案、可达性及次要性能问题 | 保留复现并按真实使用频率处理 |

## 关键使用流程

机器可读目录为 `Tests/Acceptance/catalog.json`。每项都写明预期行为、所需证据范围、历史观察和缺口，不把断言数量当作独立场景数量。

- 对话：中文、多轮、新会话隔离、取消、迟到回复、断网和额度不足；失败输入保留，不能自动重发。
- 工具：模型选择和参数、原生审核、实际执行、真实回执、独立回读和界面结果卡必须对应同一任务。保存正文与准备粘贴不代表已经粘贴或发送。
- 记忆：保存、取消、停用、重开；自动学习、跨会话召回、冲突更正、遗忘和迟到学习。召回时隔离旧版跨聊天原文，排除“碰巧从历史找到”的假通过。手动记忆的首尾空白归一化与正文逐字节保存分别验收。
- 操作逻辑：A→B→A、重复点击、暂停后停止、等待确认后取消、资源释放期间继续、重开后不自动执行。旧结果不能取得新任务的控制权。
- 灵动岛与通知：真实系统显示和点击、状态归属、过期、冷启动、权限拒绝、关闭及去重。展示夹具不授予业务控制权限，也不证明真实引擎触发正确。
- 长任务：目标、补充、子任务账本、回执和压缩检查点保留；不能恢复 100 步总上限或关闭连续执行来绕开故障。
- 性能：分别记录 App、Widget、测试进程和编译进程；至少区分首次缓存、稳定重复及前后台/重开。不把每轮杀进程后的低内存当作无泄漏。模拟器 Debug RSS 与真机 footprint 不混用。

## 证据检查与发布门槛

```bash
python3 Tools/Quality/qa_status.py --output output/qa-status.json
python3 Tools/Quality/qa_status.py --source-revision '<待发布构建的完整源码身份>' --require-acceptance
```

第一条检查目录与引用，输出逐项结果；退出 0 只表示目录和证据引用可读取。第二条才要求所有 P0/P1 项满足相同源码身份、指定证据范围、实际结果及轮数；不满足时返回非零。该工具防止范围、版本和统计口径混淆，不会把人工填写的描述变成独立产品证明。必须继续检查原始截图、接口返回和真实回执。

核心真实对话与本机工具链需要连续三轮通过。权限拒绝、取消、未知写入和冷启动等异常条件各保留独立证据。没有真实模型回包或实际工具回执，不能使用离线结果关闭这些项目。

## 缺陷记录

`Tests/Acceptance/defects.json` 关联影响、原始失败、修复位置、复测结果和剩余边界。当前已纳入通知冷启动崩溃、记忆来源误标、测试进程误识别，以及尚未通过的系统设置跳转和过期刷新时刻。

2026-10-25 新复现的测试进程误识别：旧工具只查命令行是否包含 runner 路径，引用该路径的 shell/Python 也会被当作活跃进程。现匹配专用设备实际可执行路径的 argv 起点、容器 UUID 和完整执行文件名；缺失进程时先于 UI 文件访问拒绝。十项检查在改前五项失败，改后全部通过；真实已有 runner 的 ping 也通过，没有为此重启会话。这是同一类缺陷的五个失败断言，不是五个产品 bug。

另已复现正常 OAuth 令牌轮换导致记忆学习结果被丢弃：成功解析模型结果后，旧逻辑比较新旧访问令牌字符串，将同账户的正常轮换当作连接变化。现将就绪/过期结果检查绑定到授权账户、客户端注册、验证主体、权限集合与本次授权代次，HTTP 发送前仍单独取得实际访问令牌。四个离线场景验证同账户轮换后保存与召回成功、切换账户拒绝旧结果、撤销权限拒绝旧结果，以及同账户重新授权拒绝旧结果；另检查迟到刷新不能覆盖新授权、同代次正常刷新仍能保存。实际请求头没有使用身份标记。73 项协议检查及原有 API Key 记忆服务回归通过。这些都没有联网、访问实际钥匙串或完成真实账号验收。

## 运行约束

模拟器串行，构建并发最多 2；模型请求先最小验证再逐步放量，记录请求数和失败类型。使用用户已授权的 ChatGPT 计划额度时，仍需 Sela 的官方 OAuth 用量权限；不复制其他应用令牌，不更改自动充值或购买额度。认证、模型列表和成功推理分开验收。

账户登录/验证码、真机认证，以及未授权的发送、发布、付款继续由用户处理。话筒、真实 BLE/HID、其他手机 App 和后台续航须分别有明确范围，不能用模拟器替代。
