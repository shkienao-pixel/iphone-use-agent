## 第一轮改动

- 聊天取消或切换会话后，迟到的意图识别结果不能再进入机票查询或回答模型；记忆读取结束后也重新检查请求是否仍属于当前会话。

## 第四轮：连接结果乱序与断开结果未知

同一配对内，每个服务的状态读取和整体健康检测都有独立的请求归属。旧成功和旧错误都不能覆盖更新的结果，已失效的状态读取也不能作为有效结果返回给调用方。当前连接故障会清除已有的可用账号证明；服务恢复健康本身不会重新证明账号已连接。

断开和授权发起请求期间，先撤下该服务的已连接状态，再阻止同服务的竞争读取、重复断开和重复授权发起，其他服务仍可检测。断开只有收到对应服务的明确未连接状态才算确认；取消、失败、矛盾回执或未知状态均保留“待检测”，不自动重试。此前已知的未连接快照可保留作观察，但不会掩盖断开结果仍未确认。重新配对后，旧请求的清理不能释放新请求的占用。

## 第五轮：对话指令的任务归属

## 第六轮：航班及对话历史参考的容量

## 第七轮：任务与原对话的关联

任务焦点跟随当前对话，保留页面显式选择历史任务的入口；没有手动选择时，从本对话已经保存的消息关联中取得。切换、新建或清空对话会清除显式焦点，不继承另一段对话的选择。已结束、未关联的引擎记录不再自动进入新对话参考；当前真实活动任务仍可控制，本对话已关联的历史任务仍可查看，关联消息超出最近 12 条路由窗口时也能找到。

对话发起任务时预先分配任务 ID，同时保留原对话 ID、原消息 ID 和任务文字，作为当前进程中的提交信息。直接启动、自动准备和显式授权后的启动都会把同一 ID 传给引擎，任务记录与执行指标共用该 ID。记录回调按 ID 核对，不再用相同任务文字认领请求。

延迟创建的任务只更新原对话的消息关联，不会切走当前对话、修改新草稿或取消新对话正在等待的回答。原消息被清除或已有其他任务关联时，不重建、挪用或覆盖消息。更新非当前对话时先写入真实存储，再更新内存；写入失败保留原始文件、当前草稿和错误状态。

取消准备、暂停、停止、拒绝授权、准备失败或任务草稿改变都会释放对应的提交信息。旧准备晚返回不能清除新准备的占用；取消后重新发起相同文字的任务，也不能继承旧对话请求。重新打开 App 仅从消息关联恢复历史焦点，不恢复待执行提交或自动运行任务。
