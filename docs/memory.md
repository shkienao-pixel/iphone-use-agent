# Sela 记忆

记忆实现已经接入主工程。核心库在 `PhoneAgent/SelaMemoryCore`，Xcode 使用本地 Swift Package；现有冻结源码、签名打包和源码身份流程会随 PhoneAgent 目录一起携带核心库，无需依赖旁边的实验目录。

## 页面与基础资料

“模型与记忆 → 记忆与上下文”包含本机记忆开关、从对话中学习开关、基础资料、自动学习结果与原有手动记录。页面不展示独立开发阶段、存储路径或请求 JSON 等调试文案。

首次建立独立的 `Application Support/PhoneAgent/Intelligence` 工作区，创建 IDENTITY、SOUL、USER、MEMORY 和 BOOTSTRAP 文档。身份和相处方式作为用户配置的设定；用户资料与长期事实作为参考数据。基础资料不占原有手动记忆三条检索额度。关于用户的信息保持未知，未复制实验演示、OpenClaw 或 Codex 中的个人资料。

## 从对话学习

成功回复并保存后，AssistantConversation 把原始会话 ID 和问答交给 SelaMemoryService。普通聊天积累三条新用户消息后合并整理，明确的偏好和纠正优先处理；新建或切换对话时整理尚未覆盖的内容，避免短对话被漏掉。

整理沿用当前已配置且已授权的模型、接口和 Keychain 密钥。官方 OpenAI 连接使用无搜索工具的 Responses 结构化输出；兼容服务使用现有 Chat Completions 配置。整理失败不使已经成功的回答失败。

模型只返回摘要、事实、适用范围、确定性和逐字来源。接收方、内部 ID、时间及覆盖范围由本机绑定。重复事实合并，同一属性的新明确要求替代旧值；推测保持候选，需要用户确认后才能引用。称呼、语言及沟通风格随新话题携带，其他个人事实按相关性召回。临时条件留在对应会话，已有 Work 的原始目标、补充和完成依据继续由原任务账本负责。

## 历史与删除

原有手动记忆、图片、对话档案、任务和队列均保留原位置。已完成的对话文本增量同步到新工作区，因此主界面保留近期消息时，不会丢失已经同步的更早原文。新请求结合会话摘要、较早相关消息和客户端原有的近期消息；不会重复发送同一组近期文字。附件和图像仍走原有通道，自动整理只读取文字。

其他对话的引用继续经过现有相关性筛选和引用展示，机票查询及任务路由仍不接收无关的跨聊天材料。Work 通过现有 memoryContext 回调共享身份及个人偏好，原有长任务压缩、子任务账本、暂停续跑和防重复执行逻辑没有被替换。

忘记一条派生记忆会排除关联来源并使派生摘要失效，原始聊天仍可查看；近期模型历史也会排除这些来源。首版以整条来源消息为单位，因而同一消息中其他派生事实也会一起移除。手工写在基础文档中的内容需在相应文档编辑。清空会取消和等待正在同步的记忆任务，保留身份设定并重置个人资料与长期记忆文档；不会让迟到结果重新写回。

## 记忆与意图入口

每条用户对话先调用现有 `prepareConversation`，然后把有效的个人记忆、会话摘要及手动记忆交给 `sela-intent`。路由输入分别保存记忆参考、当前关联任务/查询状态、带真实消息 ID 和时间的近期会话工作状态，以及最新用户原文。跨聊天原文引用仍通过原有聊天回答路径披露，不混入任务路由。

文字、对话听写、本轮图片、文件及相机提问使用相同入口。路由可以查看本轮明确选择的图片和文件，历史附件只保留对话文字，不重复上传。相机抽样属于临时观察资料；需要交给任务执行器保存使用时，先请用户添加图片附件。任务的实际附件由宿主绑定，模型和已存路由 JSON 不能恢复附件或执行权限。

美团对话解析复用同一份记忆和本轮附件输入，用户明确引用习惯时可据此解释商品、口味或地址关键词；实际地址、报价和订单确认继续由原生模块校验。携程使用路由解析后的具体查询，普通聊天和任务执行器沿用各自的记忆及参考资料通道。已撤回的小红书连接不由意图入口恢复。

意图结果保留模式、宿主映射的模块、相关消息 ID、实际引用的记忆 ID 与必要缺失项。当前助手回复的解释状态随原会话保存，用来恢复下一轮的待补充问题；新话题以后以最新回复为准，旧的待补充状态不自动启动任务。模型只能引用本轮输入中真实存在的 ID。

新任务和补充继续保留最新人类原文。模型通过真实 ID 选择当前会话中的原始请求、参数回答或明确引用的内容，宿主把相应原文作为独立参考交给执行器，并在任务/队列记录中保留；执行器据此检索相关记忆和加载操作 skill。长期记忆不复制进任务快照，关闭记忆后不再检索长期资料。任务进度、已完成步骤和成功依据继续使用原任务账本与工具回执。

明确的“先规划”“只解释”等请求进入聊天；引用不清或必要参数缺失才澄清。模块不可用、引用无效或模型请求失败时保留本轮输入，不通过关键词绕过意图判断。用户重新生成旧回答和点击原生卡片沿用既有受限流程，不把它们当成一条新的执行指令。

提交消息时绑定本轮模型接收方、记忆开关及任务控制状态。检索记忆期间设置改变，旧记忆不能继续发送；检索或模型返回期间任务切换，旧的暂停/继续/补充决定不能控制替代任务。

## 记忆与意图工程加固

待补充状态采用独立的来源账本，保存原始用户消息 ID、每轮参数回答 ID、实际澄清问题 ID、缺失项和原消息时间/时区。账本随澄清回复保存；下一轮回答绑定确切的 pendingIntentID。原请求、历次补充和所回答的选项问题即使超出近期窗口也会保留为引用来源；助手问题仅作为非授权参考。来源缺失、被忘记、超过本轮来源预算，或“今天/明天”等相对日期所对应的原始日期窗口已过去，须明确当前日期或完整重述后才可形成新任务；用户明确给出新的“明天”等日期时，可以继续同一请求而无需重说标题；新话题和已交接任务不继续旧的澄清状态。非时间型写作/规划不会仅因经过一天而过期；该日期校验只用于尚未交接的澄清，不限制长任务执行和恢复。

近期窗口统一为十二条，消除记忆服务已排除十二条、路由却只带十条的缺口。遇到“半小时”“改成明天”等明确指代或参数回答，本机召回结合原请求检索相关偏好；最新用户原文仍独立进入分类器，不被扩展查询替换。

记忆与手动记录组成结构化信封。路由只接受相关事实、历史召回项和手动记录的显式来源 ID，不再通过在任意正文中搜索 UUID 验证引用。明确仅讨论的请求若被模型误判为新任务，宿主会阻止执行并转入聊天；引用中的命令、工具名称和仅限制下单的只读查询仍由语义路由处理。

用户编辑、忘记或清空记忆时更新进程内召回版本。检索遇到变更会用新来源重取一次；分类或回答途中版本失效，旧结果不能继续交接或显示。已完成任务的历史与回执仍保留，忘记一条记忆不撤销已发生的操作。撤回来源的原文、紧随其后的派生回答、自动任务引用及跨会话引用一并排除；撤回名单无法核验时关闭模型历史引用，保留已知排除项，仍可提交新的独立问题。任务召回同时绑定该执行器的模型与授权设置，不会用新接收方召回的资料发送到旧接收方。

每轮本地记录记忆准备耗时、路由耗时、来源数量、上下文消息数和判定来源；诊断字段不复制记忆正文或凭据。合成评测语料在 `Skills/sela-intent/references/evaluation-cases.json`。已开启调试会话时，`intent_evaluate` 调试指令可使用当前配置的真实模型运行这些场景，结果写入该调试会话的 `intent-evaluation.json`。评测只调用分类器，不读取个人记忆或安装执行回调。分别记录分类准确率、包含传输失败的端到端成功率、有效判定覆盖率、原始模型提案准确率、宿主拦截、误操作数、额外澄清数、失败数和每例耗时；模型格式/来源拒绝计为判定失败，传输失败单列；连续三次传输失败或授权改变时停止。本机注入模型回复的回归结果不等同于这些真实模型指标。

## 并发与屏幕边界

等待聊天或云端模块返回时可以新建会话。不同会话最多四个请求并行，同一会话一次只提交一轮，避免两个回答争用同一组指代与待补充状态。每个请求固定原会话、消息、附件、记忆版本和模型配置；结果、错误、任务卡片和取消都归原会话。切回仍在等待的会话可查看或取消该轮；迟到结果不会覆盖当前输入。相机和屏幕观察会话离开时取消。

无需占用 iPhone 屏幕的原生任务使用独立 toolsOnly 执行器，最多三项同时执行；更多任务等待名额。每项独立保存目标、设置、来源、步骤、回执和恢复点。需要点击、切换 App 或 BLE 的任务继续进入单一屏幕队列，新任务不抢占当前执行。这里的后台表示不占屏幕，并不承诺 iOS 挂起 Sela 后持续运行。

分类器只给出 native/screen 提示；执行器按能力逐次校验。后台工具不得触发首次授权弹窗，未授权时保留任务并等待用户处理。会打开快捷指令的备忘录，以及不能证明无授权弹窗的健康查询，需要前台执行。共享日历/提醒、内容库、音乐等资源按资源加锁；等待与取消释放各自的租约，互不冲销其他任务。确认、拒绝、停止绑定实际任务 ID 与当前确认 ID，后台确认入口显示在原任务卡片，不自动抢占新会话弹窗。

暂停、继续、补充和停止从本轮提交时的任务 ID 与进程内会话令牌校验；模型和持久化记录不能制造这些令牌。设置改变时暂停后台任务，明确恢复后使用当前设置重新规划。重启后只展示可恢复记录，需用户继续，不自动重跑。

屏幕任务队列入口位于聊天/任务页右上角，显示未结束数量。点击打开全局队列面板，保留当前聊天草稿；当前任务固定展示，等待项可通过实际拖拽或辅助功能上下移排序。开始队列后按持久化顺序执行，执行途中调整后续顺序不抢占当前项。单项“开始”只解除该项暂停并保留原位置，队列暂停时仍需点全局开始。单项暂停会阻塞到达该位置后的推进，终止当前项会暂停整列；移除等待项保留任务历史和已产生的回执。无屏幕原生任务不进入这条屏幕队列。

当前任务完成到下一项启动之间保留切换所有权，等待输入清理结束后再读最新队列；新任务无法从这个间隙绕过队列。任务结束、全局暂停、模型/权限改变、失败和存储问题使旧自动推进失效。队列文件只保存顺序与恢复数据，不恢复进程内执行授权。


## 权限与验证

关闭记忆或自动学习后不再提交自动整理结果。接口、模型、密钥或授权变化后，旧整理请求不能写入。自动整理没有搜索和手机操作工具，也不能更改任务完成状态。记忆档案采用文件保护、排除备份、进程间锁和原子写入；损坏或未来版本档案不会被空数据覆盖。

验证入口：

```sh
swift test --package-path PhoneAgent/SelaMemoryCore --scratch-path output/memory-core-tests --jobs 2
bash Tests/MemoryIntegration/run.sh
bash Tests/AssistantConversation/run.sh
```

MemoryIntegration 编译当前原生服务和请求客户端，默认仅使用本地注入的模型响应；`--live` 可使用进程内已有 OPENAI_API_KEY 做合成对话验证，不把 Key 写进档案或输出。真实测试覆盖学习后在新对话中使用称呼及回答偏好，不代表已经在手机安装或验收。

## 2026-10-25 合并真机验收

携程 Skill 与记忆功能已合并安装到 iPhone 17 Pro Max，最终 Build 91。真机测试发现并修复了未绑定 Work 时模型仍输出 Work 范围导致整理失败、整理错误未显示，以及事实被翻译后仅匹配派生正文导致跨语言漏召回。整理请求现在按实际绑定限制可选范围；召回结合经过验证的来源原文与属性键，排除常见英文功能词，避免无关匹配。

关闭独立的旧版跨对话原文检索后，用真实模型完成：一轮英文对话后立即切换并提交学习、新对话中英文各自召回、中文更正后新对话英文召回、重复告知后仅一个有效值，以及临时机票预算仅保留在旅行会话。通过手机记忆页“忘记”测试名称后，新对话不再召回。此处是这些具体用例的验收，不代表任意语言、任意事实均已覆盖。

核心库 41 项测试、原生记忆集成及相关对话回归通过；最终模拟器基础资料页也通过原生 UI 检查。完整回执、失败版本及清理核对见 [verification.json](../output/combined-ctrip-memory-20261025/verification.json)。
