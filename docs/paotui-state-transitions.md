# 跑腿状态、迁移与权限

本表对应当前 `PaotuiSession`、Module 和订单服务的实际命令。阶段描述当前准备过程；真实引用、短时报价、读取票据和一次性许可仍需分别校验，不能仅凭阶段或历史卡片执行操作。

| 当前状态／事实 | 输入或事件 | 必要条件 | 结果与撤销 |
| --- | --- | --- | --- |
| 尚无实时 Session | 路由／界面读取摘要 | 只读取 existingSession | 返回空；不创建准备、不恢复历史卡 |
| 任一活跃准备阶段 | 本轮新文本或修改需求 | 原会话、宿主请求、当前 Session 票据 | 推进 revision，撤销旧报价／卡片／许可；旧异步结果拒绝 |
| 收集条件／待核对 | 查询费用 | 完整 ReadyRequest、已验证本会话真实引用、恢复地址已重新读取 | reading(quote)，独立读取 ID；不创建订单 |
| 任一可读取的活跃准备 | 地址／门店／状态读取 | 当前 Session／revision／凭据 epoch、对应读取 ID | 仅接受当前读取；保留独立订单事实 |
| reading | 读取成功 | 原读取票据仍有效 | 安装本次真实引用或报价；旧读取不能覆盖新需求 |
| reading | 网络失败／确定性校验失败 | 仍属原读取 | readFailed；网络读取提供重试，校验问题提供修改；取消不伪装成重试 |
| 持有当前未过期报价 | 选择／核对报价 | 本 Session 原始报价、当前完整卡片动作 | awaitingConfirmation；切换报价撤销之前高费确认 |
| awaitingConfirmation | 点击确认 | 原生会话、当前完整卡片、同报价、允许下单、无未决提交 | 消费卡片；高费先额外确认，否则产生一次性 grant |
| 具备 grant | 提交前检查 | 票据、凭据、金额与原始报价再次一致；Journal 可写 | 先原子持久化 unknown attempt，再单次发送；落盘失败明确未发送 |
| submitting | 创建回执／未知响应 | 绑定原 attempt，不依赖聊天任务是否存活 | 先保存独立事实；同实例同票据可收尾 outcome；取消聊天抑制迟到回复 |
| 提交中发生新需求／清空／换授权 | 结束旧准备 | 新 revision／新实例／新 epoch | 旧准备权限失效；在途回执仍归原尝试，不覆盖新对话 |
| unknown attempt | 人工逐笔核验 | 明确结论、时间和来源；可选用户报告编号严格校验 | stillUnknown 保留锁；其他结论仅记录用户判断；编号不成为平台订单或付款证据 |
| 保存的准备快照 | 明确恢复到原对话 | 当前凭据范围匹配；原对话仍在；无活跃请求；快照可读 | 新 Session、无卡片／报价／grant；重新读取选择地址、重新查店和询价 |
| 任一准备 | 清空／丢弃 | 对应会话 tombstone／原子删除；失败时隔离并保留字节 | 旧快照不能复活；不删除订单事实 |
| 已解决历史 + 可能的 unknown | 归档 | 不在提交；先保存受保护归档与清单，再裁剪主日志 | unknown 保留在主日志；故障只产生可核对的等同副本，不丢事实 |
| closed／旧卡片／旧票据 | 任意动作或晚到结果 | 无当前权威 | 拒绝；阶段、投影、人工报告和持久历史均不重建提交权 |

工作台和系统工具的 origin 只允许查询。系统工具的地址及门店引用只来自本任务实际输出；共同业务校验不等于共享下单权限。恢复、归档和人工核验均不是付款或取消订单动作。

主要反例覆盖在 `Tests/PaotuiConversation`、`PaotuiModule`、`PaotuiRecovery`、`PaotuiArchive`、`PaotuiOrders`、`PaotuiApproval` 和 `PaotuiDiagnostics`。真实服务与物理掉电行为不由这些离线用例证明。
