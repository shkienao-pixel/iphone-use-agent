# 本地业务流程：Build 73

2026-10-23。本轮接续速度与准确性任务书 WP6、WP7 及 WP8 的文件部分，所有操作限离线验证与本地构建；没有读取真实私聊、选择真实联系人或发送文件。朋友圈不属于本次用户指定范围。

## 已接入的入口

“记录与文件 → 小红书、聊天与文件发送”提供采集、聊天、文件三页。仅打开页面不会启动屏幕读取、模型请求或发送。

用户先保存范围，再显式开始。采集和聊天有 3 秒切换目标应用时间；手机共享、配件与校准必须已准备。导入资料使用系统文件选择器，按原始字节复制，用户可以搜索文件名、选择并调整顺序。文件发送按钮打开真正的系统分享面板，用户在目标扩展核对原件及对象。

完整证据在本机保存，界面可查看和导出。分析按钮才将已保存文字交给当前已配置且授权的模型，不创建密钥、不更改模型、不自动上传其他材料。测试只注入模型响应，没有真实 API 调用。

## 生产调用链

| 流程 | 已实现的软件链路 | 当前限制 |
| --- | --- | --- |
| 小红书 | 已存范围 → 当前真实截屏/OCR → 本地打开/返回/滚动 → 来源 ID 去重及原始明细落盘 → 检查点 → 程序统计 → 分批增量分析 | 从已打开的搜索结果开始；需要当前可见的真实笔记来源 URL，否则只存 pending；排序/筛选标签可见不证明选中态；分析只覆盖带逐字引用的可见文字主题 |
| 聊天 | 固定会话和条数/日期范围 → 首屏独立身份 → 受控滚动和唯一消息重叠 → 原始证据持久化 → 新增消息分批总结 → 引用校验 → Markdown/JSON | 初始真实 OCR 仅支持独立说明可见的内置文件传输助手；普通联系人需要真实稳定账号适配；相对时间未知，OCR 文字片段不等于完整气泡/全文；未读取媒体排除 |
| 文件/视频 | 原件搜索/导入 → 实际字节摘要与有序 manifest → 内容复核 → 提交前持久化 → 系统分享 → 分阶段回执 → 人工核验 | 实际扩展收件人、上传及消息证据无法由系统 completed 回调证明，因此始终待核验；强身份 GUI 驱动接口已实现，实际微信驱动缺失时 unsupported；扩展可能改变质量，需独立核查 |

小红书采集不逐篇调用远程模型；聊天读取不逐屏调用模型，消息合并后分批总结。已有分析片段再次执行时跳过，变化证据另存。数量、比例与分布由代码从实际明细计算，未知不当 0，缩写数量保留区间/下界。模型不能凭空补全未读图片、语音、附件或视频。

详细字段及验证条件分别见 [小红书](xiaohongshu-collection.md)、[聊天](chat-summary.md)、[文件](file-transfer.md)。

## 单控制器、恢复与长任务

工作区复用 App 同一个 CaptureService、MouseExecutor 和 PhoneHarnessRuntime；主 Engine、队列、手动工作区和校准互斥。动作只用当前 OCR 元素及真实矩形。过期画面、重复旧帧、共享/尺寸/配件变化、弹窗、校准失效和取消均停止，不改旧截图时间冒充新帧。

保存范围以实际 UUID 通告给模型，已接入 `xhs_collect`、`chat_read`（历史）、`chat_read_newer`（新增）、`chat_summarize` 和只读 `file_status`。不能用临时文字扩大范围，未暴露模型文件发送工具。

所有批次在下一次输入之前落盘。取消保留已完成证据；工作区选择**同一保存任务**继续，必须重新核验当前页面/首屏身份，不能直接重放旧坐标。原生工作区不注册为 Engine 任务，暂停后统一语音“继续”会引导回工作区，避免继续另一项旧任务。文件未知项需要先独立核查，即使换任务、操作 ID 或配件也不能自动重发。人工结果单独标记，不升级成自动核验或送达证据。

Build 72 的长任务功能保持：旧配置默认长任务；两种执行模式共用无总步数上限策略；滚动压缩保留原始要求、后续补充和子任务进度；任务历史和队列存检查点；暂停/停止等待旧执行释放输入。工作区取消同样保持忙碌到输入释放完毕。已授权的采集和聊天读取可在切换目标 App 后继续，普通手动操作仍在离开时停止；这不延长 iOS 的后台运行许可。每个本地宏仍有页数、时间和资源上限，这些边界不等于任务总步数上限。
