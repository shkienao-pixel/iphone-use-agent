# 微信 skill 合并说明

2026-10-25，本版按用户要求更新后合并，并暂停持续迭代。没有运行真实微信账号动作、调用模型服务或安装手机。

## 主工程行为

`Skills/wechat-assistant/SKILL.md` 随 App 的现有 Skills 文件夹资源打包。`PhoneAppSkillCatalog` 根据原始任务中的“微信”“朋友圈”、独立英文 WeChat / Weixin 或技能名选择固定资源；排除仅提到企业微信、WeCom 与普通标识符子串的任务。混合小红书与微信任务可以同时加载两个指南。

`VisionClient` 已有的视觉提示入口嵌入完整技能正文，并记录名称与 UTF-8 字节数；本次沿用该入口，没有添加第二套截图、蓝牙、模型客户端或任务队列。纯原生工具模式继续跳过视觉指南。引用文件供维护与离线验证使用，App 当前只嵌入 SKILL.md 正文，不能假定模型已读引用文件。

| 能力 | 指南规定的独立步骤 |
|---|---|
| 找联系人 | 输入搜索词 → 只选联系人分区 → 打开资料 → 核对身份 |
| 发文字 | 打开已核对会话 → 聚焦 → 输入原文 → 新图回读 → 单次提交 → 新图核验 |
| 浏览朋友圈 | 发现 → 朋友圈；或联系人资料 → 个人朋友圈 |
| 指定动态互动 | 结合作者、日期与内容选定动态 → 展开详情 → 分别点赞或填写评论 → 分别核验结果 |

明确的发送、点赞或评论请求沿用用户已有授权；同名对象或动态无法区分时才需要补充信息。草稿、提交与核验分别处理，结果未知时不自动重发。

## 独立核心的边界

`Experiments/wechat-skill-20261025` 保留独立 Swift 包，包含目标匹配、原子动作校验、提交账本、跨进程草稿恢复与只读结果恢复。参考图分析器只处理离线资料，不派发设备动作。包没有导入主工程，也未作为 App 的包依赖。

目前合并的是操作指南及加载入口；严格的结构化校验、独立持久化账本与恢复闸口尚未连接实时帧和实际派发器。不能把指南里的模型约束表述为 App 已经强制执行的运行时保证。后续接入须单独实现当前截图来源、身份连续性、控件归属与真实动作回执适配，不重复实现宿主能力。

既有 `phone_tool` 中的文件传输助手快捷操作保持原范围；它不是向普通联系人发送或操作朋友圈的接口。

## 验证与暂停

合并证据位于 `output/wechat-skill-merge-20261025-v6/verification.json`；独立验证入口为 `Experiments/wechat-skill-20261025/scripts/verify.py`，最新通过指针为该目录的 `verification/latest.json`。报告分别记录 Swift 行为测试、独立进程恢复、参考图处理与页面覆盖、资源加载、模拟器编译和源码身份。

无签名模拟器构建不代表真机安装、视觉模型遵循或完整业务流程通过。七张参考图中未展示点赞菜单、已输入键盘、提交前后连续帧，仍需用户后续安排真机验收。本版收尾后暂停长期目标，不创建定时任务或后台执行。
