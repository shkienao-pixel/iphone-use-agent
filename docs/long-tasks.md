# 长任务与上下文压缩

2026-10-23，Build 72 源码改动。

## 使用

“设置 → 任务执行 → 长任务模式”默认开启，旧版本保存的设置也默认开启。GUI 操作与仅系统工具模式都按任务是否完成、是否需要你处理、是否出错来决定结束；不再因达到 25、30 或 100 步自动终止。执行中仍可暂停、接管、补充或停止。

关闭长任务模式后，保留 1–100 步的手动上限。达到上限会暂停并保留原任务 ID 和进度。开启长任务模式后继续，可从新画面接着判断，无需重建任务。步骤计数保留整数溢出检查。

## 压缩内容

- 原始任务和后续补充不压缩，较新的明确要求优先。
- 子任务 ID、完成状态与用户确认依据独立保留，不因日志裁剪被删除。
- 最近 12 个语义步骤、最多 36 行动作及回执继续进入模型上下文；取屏、等待与耗时等诊断行不占用这个窗口。
- 离开最近窗口的记录在本地滚动归档。摘要优先保留最早关键回执、近期关键事件和近期普通事件，最多保留 48 条，渲染最多 16,000 字；近期记录渲染另有 24,000 字上限。
- 摘要明确报告省略的记录与截断的文字。动作理由表示曾提出或尝试的动作，不能证明成功；旧画面不能替代当前画面；缺失内容需要重新核对。该压缩不额外调用模型，也不是无损保存全部历史。
- 压缩状态随任务历史和队列检查点保存。队列支持超过 100 步的检查点；进程重启后仍需手动确认恢复，不自动重放旧动作。

完整正文、批量采集结果或大批文件应保存在本机内容文件等持久化产物中，不能只依赖动作理由或滚动摘要。用户主动清空可见日志会将剩余语义进度纳入摘要；删除任务会删除其记录。

## 运行边界

取消步数上限不延长 iOS 允许的后台执行时间。屏幕共享中断、设备锁定、蓝牙断连、模型服务报错、反复无效动作、待核验的操作结果或需要人工确认时，仍会暂停或停止。模型请求仍逐轮发送当前画面，不会把历史截图无限累积。

本轮不改模型服务、密钥、发送确认或本地流程的防重复机制。长时间等待人工确认只保留一个计时区间。运行计时记录也限制原始区间数量，并明确标记省略，避免遥测随执行时间无限增长；计时被截断的记录不能用于完整性能验收。
