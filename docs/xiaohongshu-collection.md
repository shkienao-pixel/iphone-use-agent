# 小红书本地采集与分批分析（WP6）

Build 74 实现生产调用链：当前屏幕读取 → 检查实际已选排序/筛选 → 打开当前候选 → 识别笔记 → 受控分享和复制来源 → 读取本机真实剪贴板 → 验证最终平台笔记 ID → 保存明细与断点 → 返回结果 → 滚动。`XiaohongshuCollectionDriving` 由 App 的真实截屏、OCR、局部图形识别和输入执行器桥接；离线测试注入同一接口，没有另一套采集引擎。采集不请求模型；只有实际复制的是短链时才通过注入的受限解析器取得最终来源，本轮测试没有执行平台网络请求。

## 任务与范围

`XiaohongshuCollectionTask` 保存关键词、范围、目标样本数、排序、筛选、所需字段和停止条件。支持 `currentSearchResults`，也支持具有真实 `profileID` 和已选 Notes/笔记标签的 `currentProfileNotes`。默认最多 20 页、200 次笔记尝试、120 秒、2 个没有新增来源 ID 的重复视口。目标数量没有采满时报告实际数量及缺口。

从**已经打开的搜索结果或指定主页笔记页**开始，不猜搜索词输入位置。支持无顶部“小红书”品牌字样的常见中英文搜索、结果、笔记、评论、分享和筛选面板组合锚点。

类别标签“综合”处于红色并不证明排序也是“综合”。没有明确排序证明时，本地流程点击唯一可见筛选控件，检查面板内实际已选排序和所请求筛选，再点击完成/收起并验证返回同一关键词结果。只检查现状，不替用户修改选项来凑任务条件。实际选中态需要原屏 OCR 的明确已选标记，或同一截图中控件边界内的红字加下划线/红字加粉色选中背景。仅有选项文字、另一截图的像素证据、错误排序或错误主页 ID 都会停止。面板前后截图 SHA256、OCR、所选控件和关闭结果作为 `scopeCapture` 持久化。

## 明细、身份与断点

- 笔记页直接显示完整平台来源时可直接提取；常见不显示 URL 的页面使用当前可见 Share/更多/局部像素确认的省略号 → 明确分享面板 → Copy link/复制链接 → 实际剪贴板变更。每步核验前后页面，复制后必须恢复同一笔记正文锚点，再返回原结果。
- 剪贴板文字必须来自实际读取，变更次数必须与这次 Copy 的前后记录匹配。App 后台无权读文字时暂停，保留精确变更次数，用户回到本 App 前台后通过 `completeCopiedSource` 补全；不重按复制。期间又复制过其他内容、超过 120 秒、复制未生效或中断结果不确定，都不能绑定来源。
- 前台补来源等待短链解析后重新读取最新明细，只能完成同一个 UUID、完整内容未变的 pending；期间保存的分析、其他笔记与检查点均保留。同一个 Collector 不并发补全，共享同一个 Store 的多个 Collector 第二次完成或来源变更明确拒写；较新的同 ID 笔记不会被旧 pending 覆盖。这不是多个独立 Store 或进程对同一磁盘路径的协调。取消保留原取消类型和未完成来源，失败不回落保存旧快照，也不重播分享。
- 唯一样本只接受实际 `xiaohongshu.com/explore/<24位十六进制ID>` 或 `/discovery/item/<ID>` 最终来源。受控复制的 `xhslink.com` 短链必须经解析器返回完整重定向链；原始链接、每个中间域和最终笔记 URL 都严格校验。错域、用户密码、端口、多个来源或没有最终 ID 均拒绝计数。
- 标题、正文 hash、行号、作者号和短链自身从不充当笔记 ID。无可见分享控件、未知面板或不能取得最终来源的观察仍保留为 `pending`。不猜坐标、不伪造 OCR URL、不自动重试不确定 Copy。
- 同文不同 ID 保留为不同样本。滚动后 OCR 文案相同也先重新打开并比较实际来源 ID，不能仅按文字认为是同页或同一篇笔记。
- 每次输入前保存导航断点，每个笔记批次在返回或滚动前原子落盘。取消和错误保留已有明细；重启在笔记页时先读取再返回，不重复计数。新共享或尺寸只有在重新核验相同搜索范围后才能续接，旧视口坐标清除，ID 去重明细保留；换设备暂停。
- 同一 ID 的可见文字或数量变化时保留旧版本，统计使用该 ID 的最新观察。Build 73 合法存档通过 `decodeIfPresent` 迁移，新增来源事务默认为空；旧范围证据保留并明确标记 legacy/unverified，不追认为新版选中态证明。存储损坏或版本未知时禁止覆盖。

## 字段与统计

标题、作者只在存在明确字段标签时赋值；无法判定角色的文字留在原始 OCR。正文保留当前可见文字片段，永远标为 `visible_ocr_fragments_only`，不声称全文读完。点赞/收藏/评论数量需要明确语义标签或唯一相邻数字，无标签工具栏数字保持未知。

程序从去重明细复算实际样本数、缺口、缺失数与比例、命中关键词的样本比例、数量区间及分布。`1万+` 保留没有已知上界的下界，`1.2万` 保留显示精度区间；未知不当 0。只有全部值均精确时才给精确总数。分布的分母是实际唯一可见样本，不是全站数量；跨分桶区间单列，不能强塞进精确桶。

图片内容、视频/音频、评论正文和未读正文始终明确排除。原始 OCR 可能包含图片中的文字；它也只是可见文字证据，不能支持对整张图片、整段视频或整篇笔记的内容结论。

## 采集与分析解耦

`XiaohongshuAnalysisService(store:model:)` 单独接受现有模型通道的 closure，调用 `analyze(taskID:batchSize:)`。它按真实笔记 ID、可见文字 SHA256 和无损分片组成稳定输入键，仅发送新增或文字发生变化的片段，每个 prompt 最多 14000 字符。每批结果独立持久化，中断后已分析部分不重发。没有文字时仅输出本地统计，不请求模型。

模型只允许返回 `visible_fragment_topics`：每项必须有实际笔记 ID、所提供片段的逐字摘录，以及摘录内逐字出现的主题短语。自由事实概括、数字总计、无来源 ID、虚构摘录和全文/媒体结论均拒绝保存。该约束将当前能力限定为可见片段主题摘取；它不等同于整篇笔记的语义研究报告。统计始终由程序独立复算。

`XiaohongshuCollectionStore.export(id:)` 返回 JSON，包含完整任务、去重明细、历史观察、pending、范围面板前后证据、Share/Copy/剪贴板/短链来源链、截图摘要、断点、分析分段和重新计算的统计。像素采集时间 `capturedAt` 与真实系统 idle 确认时间 `confirmedAt` 分开保存；静止旧像素有新鲜系统确认时可继续使用，不改写原始时间。

### 分析产物的受限追加

受限追加使用 `ValidatedXiaohongshuCollectionRun` 保存不可变的私有 Run。普通构造必须完整执行原生 `Run.validate()`；包装值不实现 `Codable`，存档仍按原有 Document 解码 Run，再逐项完整验证。Store 只保存这一份 canonical 包装值数组，对外返回 Run 的值副本，不另设可失配的原始数组和验证缓存。

`appendAnalysis(_:taskID:updatedAt:)` 仅从同一 Store 当前私有包装值复制原始字段，追加一个分析段并更新日期，再验证并持久化。私有受信构造只能接收包装值自身派生的结果；调用者不能提供原始 Run、跳过校验标志或修改闭包。完整验证的普通构造是基础，每次成功追加只改变新段与更新时间：笔记、历史笔记版本、来源尝试、pending、旧分析段、页面及 checkpoint 均由结构性复制保持不变，因此可以继承这些旧谓词已成功的结果。这里没有按 ID、时间、哈希或类型相等查找的验证缓存。

每次追加仍按原顺序完整执行任务、头部、预算、原有 ID 规则与日期比较，并完整验证实际追加的最后一个分析段，再核对 pending 唯一性。新增段继续使用原有有序笔记及版本，执行原生片段分割、SHA、逐字引文和 topic 检查；私有分支若没有最后一段则拒绝。生产追加参数非可选且必先 append，正常空分析存档仍通过普通完整构造读取。通用 `save(_:)`、存档初始化、直接 `Run.validate()` 与统计/导出仍完整验证全部旧新分析段、所有页面和 checkpoint；合法通用保存会建立新的完整验证基础。外部修改后的旧段或页面不能通过派生路径混入，不以字符串规范等价、类型相等或哈希相同替代原始证据验证。

分析服务保留模型返回后的取消检查、最新任务及该批笔记 ID/可见文字 SHA256 核验；核验和同步追加之间没有新 await，取回最新值以保留等待期间已保存的进度。原批次、prompt、模型结果解析和统计复算不变。完整 sorted-key JSON、40MB 上限、原子写入及原平台文件保护继续保留，成功后才更新内存。这里复用的是历史存储值的验证，不是当前 GUI、筛选、剪贴板或输入权限；它只约束同一 Store 内的构造，不提供多个 Store 或进程写同一路径的文件比较交换保证。

## 验证

运行 `bash Tests/Xiaohongshu/run.sh`。离线用生产服务和真实存储执行筛选面板核验→笔记→Share→Copy→实际 I/O 边界回放→短链解析→恢复→落盘→去重→续作→分批分析→导出。覆盖中英文、无品牌页、同文不同 ID、选中态混淆、错域、复制未生效、前台补全、取消不重按 Copy、恢复错页、遮挡、idle 静止页、旧版存档迁移等。设置 `XHS_REPLAY_OUTPUT_DIR` 可保存带完整合成来源链的 JSON，文件名明确包含 synthetic。

同一命令保留 `Tests/Xiaohongshu/XHSAnalysisWrapperChecks.swift` 的 115 项追加事务回归，并接入 `XHSDerivedValidationChecks.swift` 的 160 项旧谓词继承控制：使用实际 Store 的通用完整保存路径对照受限追加，固定 UUID/日期时逐检查点比较完整文件、返回值、原生重开和统计/导出；覆盖外部坏原始证据、旧新分析段、末页和 checkpoint 拒绝，合法通用重保存与真实关键词覆盖变化后再追加，外部值副本隔离、旧版存档、预算与原错误顺序，以及真实原子写入失败不推进内存、模型等待期间其他保存保留、证据变化与取消拒写。原有 302 项与上述控制合计 577 项；单独领域通过不等于完整发布或真机验收。

完整合成 fixture `Tests/Xiaohongshu/Fixtures/analysis-wrapper-cold10.json` 只清除既有分析段，原任务、原始明细、范围与断点字段保留，经原生 Store 重新打开后再走实际分析入口；本地模型闭包只返回来源内逐字摘录。性能回放保留完整 10/200/1000 条输入、默认 8 条批次和全部保存，旧版完整验证器独立重开每个输出。它测量的是本机离线分析追加，不代表采集、UI 或真实模型/设备耗时；通用采集检查点仍走完整验证。

这是生产逻辑的离线回放验证，未执行真实小红书、真实 OCR、蓝牙、实际系统剪贴板、平台网络或真实模型请求。不同版本/主题的图标和选中配色仍须真机核验；证据不满足时安全暂停。没有同范围的真机基线，不以离线检查耗时宣称 40% 耗时/50% 远程决策目标通过。
