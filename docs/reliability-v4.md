# 稳定性与文件管理：Build 75

本轮落实四项离线改进：减少正常内容被当弹窗的误停、逐文件人工核验、关键画面与诊断导出、原件内容复用和存储管理。没有改变长任务的步数、历史压缩、任务账本、暂停继续与停止策略；七份核心文件逐字对比本轮改前清单。

## 页面判断

`PhoneOverlayClassifier`同时检查当前 OCR 的位置、按钮组合、页面结构与实际截图像素。只有聊天气泡或连续笔记正文的图像证据充分时，才将其中的“OK／确定／允许”等识别为普通内容。缺少图像或结构不清时继续停止；权限、支付、密码、删除、重发和登录确认的独立结构仍受阻挡。受控分享菜单的取消按钮只在对应领域菜单内允许，通用操作缓存不会因此解除阻挡。

这改善的是有明确证据场景下的判断；合成像素与回放通过不代表所有真实主题、字号或 App 布局已验收。

## 逐文件核验

在“工作台 → 长任务工作区 → 文件 → 逐文件核验”中，选择实际已检查且结果相同的文件，填写在哪里检查、看到了什么，再记录“用户确认已提交／确认未提交／仍未知”。未选择的文件不变，仍未知项继续阻止重发。

每次记录保留准确文件 UUID、用户所选结果、说明和时间，不覆盖此前人工记录。旧 Build 74 回执可读取。人工确认不会升级为自动文件 hash／收件人核验、送达或已读证明，也不会触发输入或补发。只有本批全部待核验项被独立解决后，才解除相应诊断证据的保留保护。

## 关键画面与诊断

工作区新增“诊断”页，可预览原始关键画面，生成一个包含原 JPEG 字节（base64）、实际 OCR、页面结构、捕获/系统确认时间、动作与停因的本地 JSON 文件。没有自动上传；分享由用户选择目标。

生产本地 Runtime 的实际识别帧有观察记录，工作区 GUI 驱动另记录动作前、动作返回、停止和结果。动作返回仍使用动作前的真实画面，并明确说明等待后续画面核验，不伪称已取得结果截图。原生分享在可能提交边界保护相关证据；没有屏幕共享或有效画面时明确显示截图未记录，文件回执仍保留。

默认最多 250 条元数据、120 张原图、80 MiB 原图总量，单图最多 4 MiB；诊断索引上限 8 MiB。按保留优先级清理非保护记录，空间不足保留明确的“原图未保存”状态。待核验提交证据不自动清理；保护记录占满容量时本次记录明确失败，不无界增长。导出另有大小、数量和总量上限。索引与原图校验失败时保留原始数据，不以空索引覆盖。诊断内容不进入模型提示词或性能计时报告。

## 原件复用与管理

真实 SHA256 和字节数一致时，先重新核对已保存的实际文件，再尝试在本机用硬链接复用原始内容；硬链接不可用则正常复制。每次导入仍保留独立来源、文件名、时间和 artifact UUID，既有发送 manifest 不变。同名同大小而内容不同的文件不会被合并。

文件页“管理原件与空间”支持归档、恢复、删除未引用原件和显式核算空间。归档项目不再进入新的分享选择，但旧回执与原件读取仍保留。被任意回执或已保存自动计划引用的文件只能归档，不能删除。存在待核验或执行中的提交时也禁止删除；删除只针对此 App 副本，不删除文件 App 的来源。

删除使用持久化事务与同目录移动，重启时恢复未完成事务。空间核算检查实际文件内容并按真实设备/inode 统计独立文件长度；缺失、损坏或无法核对时保留未知，不报告为零。复用节省量是原件逻辑副本长度，不等于手机整个 App 的实际磁盘占用。

## 验证范围

`bash scripts/check.sh`执行原有回归与新增 OverlayRecognition、FileReview、FileLibrary、WorkflowDiagnostics；WorkflowIntegration直接运行生产 Runtime → 原图桥接 → GUI 输入边界 → 诊断存储/导出/清理。所有外部 I/O 均为明确的离线替身，只在临时目录操作合成原件与图片。

最终数量、双平台无签名编译、源码摘要、完整源包及可应用差异以 `output/reliability-20261023-v4/verification.json` 为准。没有读取真实私聊或系统剪贴板，没有发送文件、调用真实模型、安装手机或验收真机权限/蓝牙/后台表现。微信自动发送的严格身份与原件证据条件保持不变，详见 [Build 74 说明](domain-adapters-v3.md)。

诊断存储的上限、导出格式及故障处理详见[诊断说明](workflow-diagnostics.md)。
