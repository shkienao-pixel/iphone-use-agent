# 滴滴打车在 Sela 统一工程中的适配

统一工程同时保留携程机票、火车票/汽车票与滴滴路由。滴滴能力仍由 `Skills/didi-ride/SKILL.md` 约束：模型识别实际打车/估价请求后，在所属会话显示原生卡片；只讨论时保持普通对话。请求原话与唯一关联的补充保留，搜索草稿不是已核验地点，必须搜索并选择实际 POI。

## 查询与模拟边界

地点搜索、地址解析、附近地点和车型估价来自用户主动连接的滴滴 MCP。所选查询坐标及主动定位坐标会发送给滴滴；城市、地点及坐标需用户核对。仅本卡当前搜索缓存中的核验地点可用于估价。定位、地图或外部构造的“已核验”标记不会被静默替换为其他 POI。经停点不计入当前估价，并持续显示“直达预估，未计经停”。

接单、演示司机、DEMO 车牌和接车进度均为本地模拟，不创建、取消或支付真实订单。未知价格显示“待核实”，真实返回的零价才显示零。

## 生命周期与重开修复

- 地点按钮的整个矩形区域可点击，包含文字之间的空白，不再仅依靠文字和铅笔图标命中。
- 嵌入卡保留顶部“结束”，底部新增可滚动到的“结束本次模拟”次要入口，整行命中区至少44点；两处调用同一关闭、取消与断开路径，避免顶部被系统浮球遮挡时没有退出入口。
- “再体验一次”取消旧任务并清空起终点、经停、车型、报价、临时位置和搜索核验缓存，回到地点步骤。同一张仍连接的卡保留内存连接，避免无必要地重新输入凭据；所有地点必须重新搜索选择。
- 行程代次独立于连接代次。重开后，即使旧请求未及时响应取消，迟到的搜索或估价也不能回填新行程。
- 更正请求时清空已选行程与核验缓存；结束、断开或卡片消失时立即清凭据和临时数据。进程重启不恢复活动模拟、连接或位置。
- 凭据、精确位置和查询缓存不写入会话存档、偏好、钥匙串或日志；当前用户输入的公共地点请求原文本身仍属于普通会话内容。

## 验证入口与边界

`bash Tests/DidiSimulation/run.sh` 使用生产服务、生产价格展示类型及会话归属注册表，通过内存 HTTP transport 构造响应，覆盖缺价与真零、空车型、服务错误、缓存作废、重开后的迟到搜索/询价、断开后迟到连接和会话所有权。该套件不联网、不导入凭据、不操作系统定位或设备，不能替代真实模型、实际滴滴权益、坐标精度或真机触摸验收。

统一版的构建、安装、真实服务与 UI 验收以本轮测试结果为准。旧独立版的通过记录不能自动变成统一版结果。
