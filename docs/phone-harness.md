# iPhone 操作 Harness

Harness 给模型提供手机操作词汇、当前页面的可用控件和已验证布局。模型可以说“打开搜索”“点这个控件”“输入文字”，不必每次重新推算所有坐标。App 负责解析请求、找位置和执行，开发板继续通过蓝牙 HID 发送鼠标与键盘输入。

## 模型工具协议

模型动作使用 `kind: "phone_tool"`，`text` 是下面请求对象编码后的 JSON 字符串。只允许 `operation`、`target`、`text`、`operation_id` 四个字段；未用字段可省略或设为 `null`。

| operation | 参数 | 用途 |
| --- | --- | --- |
| `tap` | `target` | 点击当前观察中列出的控件 ID 或唯一、完整的标签 |
| `open_search` | 无 | 打开主屏搜索 |
| `open_app` | `target` | 使用搜索打开指定 App |
| `back` | 无 | 在支持的页面返回上一层 |
| `home` | 无 | 使用已配置的 Home 输入回主屏 |
| `type_text` | `text` | 在已经聚焦的输入框输入文字 |
| `press_key` | `target` | 发送支持的键盘按键，如 `ENTER` |
| `wechat_send` | `target`、`text`、`operation_id` | 在可识别微信页面完成内置文件传输助手的短 ASCII 单条流程；各阶段严格核验，失败不重放 |

例如，模型先返回：

```json
{"kind":"phone_tool","text":"{\"operation\":\"open_search\"}","reason":"打开主屏搜索"}
```

输入与点击控件的工具内容分别是：

```json
{"operation":"type_text","text":"Settings"}
```

```json
{"operation":"tap","target":"当前观察中提供的控件 ID"}
```

控件 ID 来自当前观察，不能编造；标签匹配要求规范化后的完整文字唯一，不能用模糊包含匹配决定点击。`type_text` 目前通过 HID 输入最多 500 个 ASCII 可打印字符；中文等 Unicode 输入会被拒绝。`open_app` 的名称可以包含中文，但搜索输入仍受现有键盘能力约束。

`open_app` 在本地连续执行“主屏搜索 → 全选已有内容 → 键盘输入 → 点击唯一应用结果”，中间用新画面检查页面、遮挡和结果。它只接受“应用 / Apps / 应用程序”应用分区中的唯一匹配，不凭网页、联系人或 Top Hit 中的同名文字打开。搜索焦点须由本地打开搜索流程确认；按键通过 HID 直接发送，不逐个点击屏幕键盘。单独的 `type_text` 只填一个字段，回车和 Tab 需要明确调用 `press_key`。返回主屏仅在已确认配件的 Home 映射时发送对应输入。

## 布局如何学习和复用

当前观察先给出页面、设备布局标识和控件矩形，矩形坐标归一化到 `0...1`。布局记忆只保存有实际操作结果支持的路径：主屏搜索入口必须观察到 `home → search`；返回入口必须观察到设置子页返回设置页面。只有在原页面确实存在的控件、同一设备布局、时间顺序正确且没有遮挡时才能记录。一次按钮命令发送成功不能证明页面跳转成功。

复用时核对设备布局、来源页面、记忆版本、时间有效期以及遮挡状态，超过 30 天或来自未来的记录不可用。布局变化、键盘、系统弹窗、辅助功能与文字尺寸变化可能改变位置；旧记忆不能单凭“iPhone 界面通常稳定”继续点击。无法确认的位置回到观察流程，首次遇见的页面仍需要识别。

OCR 控件 ID 绑定捕获流与像素采集时间，模型上一帧的 ID 在新像素帧中不会指向占据同一位置的新对象；同一真实像素帧可以复用 ID。普通按文字点击仍只表示当前唯一文字目标，不证明联系人或笔记的业务身份。

当前画面的 OCR 按捕获流 `captureID` 和像素采集时间 `capturedAt` 缓存，同一画面不会反复识别。宏内部每次实际操作后等待新画面，引擎核对捕获流和源尺寸；共享来源改变时立即停止后续动作。布局保存在 App 本机的 `phone-layout-memory.json`，排除系统备份；模型请求复用网络会话，减少重复连接开销。

## 复用与等待优化

页面切换可能先返回原页或动画画面。本地导航现在最多观察 12 个新画面、等待 2 秒来确认目标状态，期间不重发点击或输入；遮挡、取消、采集错误、共享来源或尺寸改变会立即停止。超过上限交回模型核对当前页面。打开 Settings 会校验实际设置页面；尚无本地身份识别的 App 仍由模型核对，不能仅凭离开搜索页宣称已打开目标。

执行回执同时携带真实的末次输入完成时刻和已观察的结束画面。引擎只在同一捕获流、尺寸匹配、画面晚于末次输入且在 1.5 秒有效期内时，复用该画面进入下一轮，省去重复等待。没有输入的幂等结果、超时、部分失败或过期画面不走这条路径。模型返回动作后，仍需独立获取并核对当前画面再执行。

模型历史按最近 12 个实际决策步保留动作及回执，最多 36 条；计时、指针唤醒和画面等待留在诊断日志中，不再挤占模型的操作历史。日志另外分别记录取屏、本地识别、模型等待与输入执行耗时，便于真机比较。

`keyboard_focus_confirmed` 表示本地是否确认输入焦点。蓝牙键盘就绪不等于编辑器已聚焦；备忘录等 App 隐藏屏幕键盘时，本地目前无法可靠识别通用编辑焦点，此字段为 false 时不要反复请求 Harness 输入，应根据当前画面使用原单步键盘操作。Unicode 长文仍需要已准备的手机剪贴板或其他已验证输入途径；本轮没有改变固件或缩短硬件键入间隔。

## 验证范围

在装有 Xcode 的 Mac 上运行：

```sh
bash Tests/Harness/run.sh
bash Tests/HarnessRuntime/run.sh
bash Tests/HarnessWorkflows/run.sh
bash Tests/HarnessReuse/run.sh
bash Tests/ModelHistory/run.sh
```

离线检查覆盖工具输入边界、坐标有效性、标签歧义、记忆隔离/失效以及页面转换证据。脚本只编译共享逻辑并使用构造的页面数据，不连接手机、开发板、蓝牙或模型接口。

运行时检查编译生产 `PhoneHarnessRuntime` 和 `AgentEngine`，仅注入 OCR 文本矩形与离线输入/模型探针，验证本地打开 App、模型动作路由、遮挡和目标校验、返回入口学习/持久化、取消及共享来源变化。它不验证真实 OCR、BLE/HID 时序或真机点击精度。

回执复用检查执行生产引擎，验证结束画面进入下一次模型观察之前不再额外唤醒，并确认模型返回后的独立核验仍然存在；过期、不同捕获流和部分失败的回执必须重新取屏。历史检查向同一 instruction 构造器注入诊断噪声，并重放真实备忘录日志，核对粘贴、保存及重新打开的历史仍保留。

这些检查不能证明真机已经学会布局、鼠标点得准，或操作速度达到浏览器工具水平。端到端耗时、模型调用次数、点中率和错误恢复需要在同一个真机任务上另外测量；本版实测摘要见 [2026-10-23 版本说明](version-2026-10-23.md)；原始真机记录仅保存在本地，不纳入仓库。


## 保守页面适配与本地微信流程（本轮新增）

生产 `PhonePageAdapters` 使用当前 OCR 文字及相邻区域的多项锚点，保守标记微信列表、搜索、聊天、朋友圈，以及小红书搜索、结果、笔记、评论。上下文包含 `page_identity_evidence` 与 `page_identity_basis`，识别依据明确是当前 OCR 结构。只有“搜索”“评论”或聊天标题等单项文字不够；缺少品牌、导航或输入结构时返回 `unknown`。这些启发式尚无真机截图用例证明覆盖当前 App 版本和主题，小红书页面识别也不代表采集/互动流程已经实现。

`wechat_send` 示例：

```json
{"operation":"wechat_send","target":"文件传输助手","text":"hello","operation_id":"self-hello-test-0001"}
```

边界是内置文件传输助手（当前实际标题须精确等于 `文件传输助手`、`File Transfer` 或 `File Transfer Assistant` 中的所请求值）。普通联系人仅有显示名不能建立稳定身份，当前拒绝使用此宏给普通联系人发送；即使名称相同，也必须同时存在位于聊天顶部中央宽行的独立手机/电脑互传系统说明，缺失则停止。这仍是保守 OCR 结构证据，没有平台内部联系人 ID，不能对伪装或未知版本声称绝对身份认证。正文为 1～80 个单行可打印 ASCII 字符；中文及长文仍由内容产物工作流处理。

起点必须是当前已识别的微信列表、搜索页或目标聊天页。当前列表里目标缺失、出现两个同名、列表滚动/插入后没有唯一当前目标时，不按旧行位置执行；不自动滚动寻找未见对象。从固定主屏打开微信并进入该起点仍需要外层导航，整条真机基准尚未验收。

流程最多派发四个输入（当前会话行、显式空输入框、一次整段输入、当前发送按钮）。每次输入后最多观察 12 帧、等待 2 秒；流程检查 10 秒总时限，进入每个后续阶段前检查截止时间。已有单次底层输入仍遵守自身超时与取消，10 秒不是强行中断底层 HID 命令的保证。每次真实输入均先原子写入检查点；等待只看结果，不重发动作。

输入框必须在当前 OCR 中存在 `发送消息` / `Send a message` / `消息` / `Message` 等显式空字段文字，且处于已识别聊天的输入区域。聚焦后需要同一会话、空字段和可见屏幕键盘；输入后必须在与唯一发送按钮同一行的字段中读回完整短文本。**真实微信主题若没有可识别占位文字，将安全回退，当前不会依据空白区域猜输入坐标。** 这项限制使部分实际页面尚不能自动跑通，不能用离线宏测试代替真机证明。

提交前要求可见范围里没有已有同文右侧消息；发送只派发一次，之后同时核对原会话及互传说明、空输入框、发送按钮消失、恰好一条完整同文右侧气泡，并要求提交前所有可见消息锚点在邻近原位置保留。视口变化、滚动出旧气泡或缺少原锚点均保留待核验，不能靠计数猜新消息。完成状态是 `observed_submission`，只证明当前可见 UI 出现一条，不能证明全部历史里仅一条、服务端送达或对方已读。未核对完成返回 `partial_pending_review`，不能把发送命令成功记为完成。

检查点保存在布局文件旁的 `phone-layout-memory.workflows.json`，使用原子写入、手机数据保护并排除备份。v3 记录绑定 `operation_id`、宿主任务 ID、规范化内置会话身份、完整短文本、手机 `identifierForVendor` / BLE 配件和阶段。业务幂等身份与字体、缩放、方向、App/OS 版本及屏幕布局完全分离，改大小写、使用中英文别名或改变布局不能绕过。布局记忆自身仍按当前 App 版本、OS、字体、粗体、缩放、方向/源尺寸和配件隔离；外部微信/小红书 App 版本未被读取，不保存其业务坐标记忆。读取损坏、重复 ID、版本不兼容或写入失败时禁止继续。待核验记录不自动过期或淘汰，避免重放窗口。相同 ID 重入只返回持久化阶段；未知输入或发送结果禁止重输/重发；同一任务的已观察终态也不能换新 ID 再提交同一内容。待核验状态阻止其他 GUI 操作及新任务/恢复，从引擎直接进入 `needsUser`，防止模型改用普通点击、输入和按键绕过回执。已完成 ID 仅返回历史观察，不伪造新的已验证画面。取消仍向外层传播，取消前检查点保留。只有用户在设备页明确核验“确认已提交”或“确认未提交”，才写入 `reviewedByUser` 人工终态并释放待核验门禁；人工终态与 OCR 观察成功分开记录，不自动重发或承诺送达。坏存储无法被当成空回执开始新任务。

| 离线用例 | 生产逻辑实际结果 |
| --- | --- |
| 8 类页面的构造 OCR 锚点、单锚点缺失 | 保守识别或明确未知 |
| 同名目标 | 不点击，返回部分待核验 |

| 过期画面、慢 OCR 后过期、共享切换、损坏持久化回执 | OCR 后与派发前重新核对，拒绝不新鲜/错误来源 |

`Tests/HarnessWorkflows/run.sh` 编译生产 Runtime/Engine/Adapter，注入构造 OCR 矩形和离线输入探针，执行以上分支。没有真实 OCR、微信/小红书、手机键盘、BLE、消息发送、送达或真机耗时数据。真机页面覆盖、固定主屏到发送全流程、≤60 秒/≤5 轮和同条件三次前后对照仍待验收。

## Build 74 已保存适配

`file_send(target=automatic_file_tasks UUID)`仅执行原生用户保存的准确账号、原件和顺序；计划 UUID 固定作为发送操作 ID。必须在 Phone Agent 前台且长任务工作区的实际分享宿主可呈现。原件校验后重新核对宿主，未呈现前不符合条件则不创建提交回执。进入可能提交窗口后未知不重发。`file_status`在待核验状态仍可只读查看，其他 GUI 操作继续阻断。
