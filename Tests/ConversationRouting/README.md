# 对话路由与模型请求回归

运行 `bash Tests/ConversationRouting/run.sh`。编译真实的统一路由器、共享输入模型、VisionClient 与 ConnectedConversationClient，仅将两个 HTTP `load` 方法体替换为本机收集器。系统说明、消息构建、长度限制、授权检查、回复解析和取消逻辑均为当前生产实现。

两条模型路径验证固定路由说明、历史参考与最新问题的角色分离，完整 4000 字输入，独立的参考资料预算，历史条数/长度限制，文字路由不携带历史附件像素/正文，空白与非法路由、截断/拒绝/HTTP 错误/超时/异源响应、授权撤回和迟到取消。另检查普通问答继续使用自然语言说明与本次附件，以及兼容的 token 参数和 JSON 格式开关。

记忆与意图检查覆盖始终加载真实打包的 `sela-intent`、记忆的独立预算与参考角色、待补充问题和真实消息 ID、本轮图片/文件/相机画面的两种请求编码、宿主绑定附件、逐字任务参考，以及拒绝伪造记忆/消息 ID。意图输出使用本地注入值；这些检查验证数据确实进入分类器及后续分发，不证明真实模型的分类准确率。

地址检查覆盖 HTTPS scheme/host 大小写、隐式与显式 443 同源、不同端口与 HTTP 降级的拒绝，以及保留自定义端口和查询参数。官方 Responses 路径只在完整配置符合标准入口时选用，其他配置保留原 Chat Completions 地址。

路由回复预算使用当前配置，测试只证明请求参数与解析逻辑一致，不证明真实模型能在该预算内完整理解或返回长任务。历史图片使用头部哨兵检查请求编码，不代表可解码图片或真实视觉理解；实际图片解码由原有附件导入检查覆盖。

收集器故意在门控期间忽略取消，返回前冻结旧响应，以确认生产代码仍拒绝它。失败时保留提取后的客户端、原始源码、提取摘要、执行文件及结果 JSON；可用 `PHONE_TEST_SOURCE_ROOT` 指向旧源码重放相同检查。

没有网络、真实模型、账号凭据读取、手机输入或自动任务执行，也不代表模型意图判断准确率和真机验收通过。
