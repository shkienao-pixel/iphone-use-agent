# 同一配对下的请求顺序与连接变更

运行 `bash Tests/BridgeOrdering/run.sh`。使用 BridgeIdentity 的提取器，编译原样的生产连接协调器。默认值、凭据和 HTTP 由内存替身提供；每次回复在请求进入时冻结，分别门控交付，覆盖 3 个同账号检查的全部 6 种返回顺序。

检查旧成功/旧失败不能覆盖新账号或健康证据，断开前的读取不能重新标记已连接，当前连接失败会撤销旧可用证据，单纯健康恢复不会虚构账号核验。验证不同服务可独立检查，以及当前失败后可通过新检查恢复。

断开和授权/准备请求占用同账号的变更权限。检查并发读取、重复断开或授权不会进入传输；其他服务仍可检查；旧配对请求的收尾不能释放新配对的占用。断开中撤销 ready 使用的 connected 状态；失败、取消、矛盾或未知回执保持待检测，不能自行重发。此前已确认的未连接观察可以保留，但不能据此把未知断开当作完成。

检查使用公开的 `statuses`、`bridgeAvailable`、`statusLabel` 和调用者收到的结果，未读取内部请求 UUID。页面直接读取的 connected 标记在待核验时不能为真。该检查不渲染 SwiftUI，不证明真实服务端写入顺序、实际授权、网络原子性或 iPhone 验收。特别是 HTTP 已取消但服务端仍处理的情形只能保持未知并重新核验，不能推断已经撤销远端动作。

失败时保留原始提取源码、执行文件和结果 JSON。可用 `PHONE_TEST_SOURCE_ROOT` 指向旧源码，重放同一组门控场景。
